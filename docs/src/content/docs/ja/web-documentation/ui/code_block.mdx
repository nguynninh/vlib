コードブロックは、技術ドキュメントのページの中で読者が最も長く滞在する場所です。良いコードスニペットは構文的に正しいだけでなく、どの言語で書かれているか、どのファイルに属するか、どの行に注目すべきかを読者に伝える必要があります。

このページでは、現行のドキュメントシステムと一貫性のある形で MDX にコードブロックを書く方法を説明します。

## 基本構文

コードブロックはバッククォート3つで始まり、その後に言語識別子を続けます。ドキュメントがレンダリングされる際、システムはこの識別子を使ってシンタックスハイライトを適用します。

````mdx showLineNumbers
```ts
const message: string = "こんにちは";
console.log(message);
```
````

結果として、コードは TypeScript として表示されます。

````typescript title="hello.ts"
const message: string = "こんにちは";
console.log(message);
````

`ts` を省略してもコードは表示されますが、シンタックスハイライトが失われ、ページの見通しが悪くなります。

````
const message: string = "こんにちは";
console.log(message);
````

:::danger
コードの内容として、このページの MDX 例のようにフェンス付きコードブロックを別のブロックの中にネストして表示する必要がある場合、外側のフェンスは内側より多くのバッククォートを使わなければなりません。たとえば内側が3つのバッククォート ``` なら、外側は4つ ```` にします。同じ数を使うと、MDX がコードフェンスを誤った位置で閉じてしまい、ページの残りの部分が崩れます。
:::

## 適切な言語を選ぶ

実際のコード内容に合った言語を宣言してください。これは小さな違いですが、ユーザーが読み、コピーし、デバッグする際の使いやすさに直接影響します。

<Tabs>
    <TabItem label="TypeScript">
        ````mdx showLineNumbers
            ```ts title="src/main.ts"
                const app = createApp();
                app.start();
            ```
        ````
    </TabItem>
    <TabItem label="Java">

        ````mdx showLineNumbers
            ```java title="src/main/java/Main.java"
                public class Main {
                    public static void main(String[] args) {
                        System.out.println("こんにちは");
                    }
                }
            ```
        ````

    </TabItem>
    <TabItem label="JSON">
        ````mdx showLineNumbers
            ```json title="package.json"
                {
                    "scripts": {
                        "dev": "astro dev",
                        "build": "astro build"
                    }
                }
            ```
        ````
    </TabItem>
</Tabs>

`ts`、`tsx`、`js`、`java`、`kotlin`、`json`、`css`、`scss`、`bash`、`diff`、`mdx`、`text` のような短くて一般的な識別子を使うことをおすすめします。

:::caution[警告]
このリストには含まれない特別な識別子が1つあります。`mermaid` です。これもフェンス付きコードブロックですが、中身は通常のシンタックスハイライト対象のコードではなくダイアグラムの記述なので、独立したページがあります。詳しくは [Mermaid ダイアグラム](/ja/web-documentation/ui/code_block_mermaid) を参照してください。
:::

:::note
コードが特定の言語に属する場合は、必ず言語識別子を宣言してください。言語なしのコードブロックは、純粋なプレーンテキストの内容にのみ使用してください。
:::

## ファイル名を追加する

サンプルが特定のファイルを表す場合は、`title="..."` を追加して、読者がコードをどこに配置すべきかわかるようにします。

````mdx showLineNumbers
```tsx title="src/components/Button.tsx"
export function Button() {
    return <button>購入手続き</button>;
}
```
````

`title` は、インストール、設定、マイグレーションのガイドや、読者が特定のファイルを編集する必要があるあらゆる例で特に役立ちます。

## 行番号を表示する

行番号は説明をより正確にします。「下の設定ブロック」と言う代わりに、「3行目でビルドスクリプトを宣言している」と言えます。

````mdx showLineNumbers
```json title="package.json" showLineNumbers
{
    "scripts": {
        "dev": "astro dev",
        "build": "astro build"
    }
}
```
````

すべてのコードで `showLineNumbers` を有効にする必要はありません。1〜2行の短い例では、行番号があまり価値をもたらさないことが多いです。

## 重要な行をハイライトする

サンプルの行数が多く、注目すべきなのがその一部だけの場合は、コードフェンスのメタ情報の後に `{}` で行番号を追加します。これにより、読者は重要な部分にすぐ目を向けられます。

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {3}
const app = createApp();

app.use(paymentPlugin);
app.start();
```
````

````ts title="src/main.ts" showLineNumbers {3}
const app = createApp();

app.use(paymentPlugin);
app.start();
````

連続する複数行を強調したい場合は範囲を使います。

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {3-4}
const app = createApp();

app.use(paymentPlugin);
app.start();
```
````

````ts title="src/main.ts" showLineNumbers {3-4}
const app = createApp();

app.use(paymentPlugin);
app.start();
````

強調したい行が隣接していない場合は、カンマで区切ります。

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {1,4}
const app = createApp();
const config = loadConfig();

app.start(config);
```
````

````ts title="src/main.ts" showLineNumbers {1,4}
const app = createApp();
const config = loadConfig();

app.start(config);
````

## 変更点を diff で書く

コードの修正を説明するドキュメントでは、「変更前」「変更後」の2つのブロックを並べるより、`diff` の方がわかりやすいことが多いです。

````mdx showLineNumbers
```diff
- const environment = "development";
+ const environment = import.meta.env.MODE;
```
````

diff は、マイグレーション、バグ修正、設定変更など、どの行がどう変わったのかを読者に正確に伝えたい場面に適しています。

## 複数の実装には tabs を使う

同じ考え方に対して複数の同等な実装がある場合は、ページが長くなりすぎないように tabs にまとめます。読者は文脈を保ったまま、自分が使っている言語やフレームワークを選べます。

````mdx title="docs/src/content/docs/example.mdx" showLineNumbers
import { Tabs, TabItem } from '@astrojs/starlight/components';

<Tabs>
	<TabItem label="Java">

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("こんにちは");
    }
}
```

	</TabItem>
	<TabItem label="Kotlin">

```kotlin
fun main() {
    println("こんにちは")
}
```

	</TabItem>
</Tabs>
````

tabs は、それぞれのバージョンが本当に互いの代替になる場合に使います。各ブロックが同じ手順の中の異なるステップを説明している場合は、別々のセクションに分けてください。

## 推奨される使い方

良いコードブロックには通常、言語・ファイル・注目すべき部分という3層の文脈がすべて含まれています。

````mdx
```ts title="src/main.ts" showLineNumbers {4}
import { createApp } from "./app";
import { paymentPlugin } from "./plugins/payment";

const app = createApp();
app.use(paymentPlugin);
app.start();
```
````

これは、次のような素のブロックよりも優れています。

````mdx showLineNumbers
```
const app = createApp();
app.start();
```
````

2つ目のブロックも表示はされますが、文脈が欠けています。言語も、ファイルも、どの行が重要かもわかりません。

## クイックチェックリスト

ドキュメントページを仕上げる前に、コードブロックについて次の点を確認してください。

* コードブロックに正しい言語識別子が宣言されているか?
* コードが特定のファイルに属する場合、`title` が付いているか?
* `showLineNumbers` は実際に説明を追いやすくしているか?
* 変更された行や重要な行をハイライトする必要があるか?
* 複数の実装がある場合、tabs にすることでページが読みやすくなるか?
* コードが修正手順を示すものなら、`diff` の方が2つの別ブロックより明確か?

## まとめ

コードブロックは、読者がすばやく理解し、正しくコピーできるように助けるものであるべきです。まず言語識別子から始め、特定のファイルがある場合は `title` を追加し、`showLineNumbers` と意図的なハイライトを使い、そして `diff` や tabs がサンプルをより明確にする場合はそれらを選んでください。
