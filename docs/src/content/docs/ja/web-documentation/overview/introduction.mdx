## 概要

**Web Documentation** は、構造化され、検索可能で、メンテナンスしやすいナレッジベースを技術文書向けに提供する、Web ベースのドキュメントプラットフォームです。

このプラットフォームは主なコンテンツ形式として **MDX** を採用しており、必要に応じて標準的な Markdown とインタラクティブなコンポーネントを組み合わせることができます。

このアプローチにより、ドキュメントの内容はシンプルで読みやすいまま、より高度な技術文書を構築するための柔軟性も確保されています。

## 目的

Web Documentation プラットフォームは、以下を目的として設計されています。

* 技術文書を明確な階層構造で整理する。
* ドキュメントをバージョン管理された MDX ファイルとして保存する。
* Markdown 構文とカスタム MDX コンポーネントをサポートする。
* ドキュメントページ間の高速なナビゲーションを提供する。
* コード例や技術的な図（Mermaid）をサポートする。
* ドキュメント全体を対象とした全文検索を提供する。
* ライトテーマとダークテーマをサポートする。
* 複数言語をサポートする。
* デスクトップ、タブレット、モバイルに対応したレスポンシブな体験を提供する。

## ドキュメント構成

ドキュメントはいくつかの主要な領域に整理されています。

```text
Web Documentation
│
├── Overview
├── Architecture
├── Development
├── Documentation
├── UI
├── Features
├── Deployment
├── Maintenance
└── Changelog
```

各セクションは、アーキテクチャや開発から、デプロイ、保守に至るまで、プラットフォームの特定の側面に焦点を当てています。

## コンテンツ形式

ドキュメントページは **MDX** を使って書かれています。

```mdx title="src/content/docs/ja/example.mdx"
---
title: "はじめに"
description: "Web Documentation プラットフォームの紹介。"
---

## はじめに

これはドキュメントページです。

<CustomComponent />
```

MDX は Markdown のシンプルさを保ちながら、コンポーネントをドキュメントページに直接埋め込むことを可能にします。

## 対象ユーザー

このドキュメントは主に以下の読者を対象としています。

* このドキュメントプラットフォームに携わる Web 開発者。
* 新しいドキュメントページを追加する開発者。
* プラットフォームを担当するメンテナー。
* デプロイを担当する DevOps エンジニア。
* ドキュメントの内容を維持するテクニカルライター。

## 基本原則

このプラットフォームはいくつかの原則に従っています。

### シンプル

ドキュメントは書きやすく、読みやすく、更新しやすいものであるべきです。

### 構造化

コンテンツは予測可能な階層構造に従い、ユーザーが必要な情報を素早く見つけられるようにするべきです。

### バージョン管理

ドキュメントはソースコードと一緒に保存され、Git を通じて管理されます。

### 拡張性

MDX コンポーネントにより、基盤となるコンテンツ形式を変更することなく、追加のインタラクティブな機能をドキュメントシステムに組み込むことができます。

### 保守性

プロジェクト構成とドキュメントの規約により、将来の開発者がシステムを理解し、保守しやすくなります。
