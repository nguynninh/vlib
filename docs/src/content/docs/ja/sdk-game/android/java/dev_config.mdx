## 設定手順

1. Hubでの設定

    Hub上での設定が成功したら、このデータをSDKにコピーして各フィールドが正しいか確認し、他のゲームと同様にFirebase Remote Configにも設定してください。

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image4.png)

    1. Global

        すべての自動生成されたアプリケーションに適用され、誤りがない限り修正不要（誤りがあればBE側に修正を依頼）。デフォルト値は0

    2. App

        iOSを含むすべてのpackageに適用され、パラメータはappIdから取得

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image5.png)

    1. Package

        単一のpackageに適用され、packageIdから取得

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image6.png)

    2. 設定パラメータ一覧

2. Firebaseでの設定

    1. アプリケーションの設定

        アクセス先: Setting -> General -> Add app -> package Idを入力

        **Đấm Trưởng Phòng** アプリを作成後、Google Cloud上の設定を更新してgoogle-service.jsonの情報を補完する

        jsonの確認先: https://dandar3.github.io/android/google-services-json-to-xml.html

        図の通り十分な情報が必要

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image8.png)

    2. サーバーからの通知設定

        google-server.jsonをサンプルアプリに正しく設定すれば必ず通知を受信できる。事前にFirebaseのメッセージでテスト可能

        Project Setting -> Services account

        必ず1回のみ作成し、このファイルを保管すること。

        AndroidとiOS両方のHub設定を作成した後、hub上のpackage設定から通知を再テストする

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image9.png)

        Hub上での設定

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image10.png)

4. サンプル設定

    他のプロジェクトを参考にしてください

    - package nameの変更
    - プロジェクト名の変更
    - string.xmlの情報の変更
    - google-service.jsonの変更
    - vtvlive_config_sdk_game_defaultsファイルの変更 -> hubから情報を取得
    - sdk gameとgame trackingの2つのライブラリをダウンロードするためのキーの変更。accesstokenキーの作成 -> developer -> read-apiを行い保存

5. サンプルテスト手順

    1. 通常ログイン

        失敗 -> Hub設定とサンプルプロジェクトのpackageおよび発行情報が正しいか確認 -> 正しければBE側にログイン設定が完了しているか確認依頼

    2. 登録とパスワードを忘れた場合

        失敗 -> ログを開くとpackage nameがrecaptchaに存在しないと表示 -> **Đấm Trưởng Phòng** で設定

        失敗 -> BEからのエラーダイアログが表示 -> 端末やネットワークがrecaptchaによりスパム判定されている場合、別の端末や3Gネットワークを使用

    3. Googleログイン

        情報の認証に失敗。

        原因:

        -> ビルドしたアプリケーションが未署名、またはGoogle Cloud上の署名が誤っている。Apk、Google Cloud、storeの3箇所のsha1署名が一致しているか確認が必要

        ! Hub上のGGログインclient IDの設定が間違っている可能性あり

    4. Facebookログイン

        ログインできないというエラー。

        develop環境の場合:

        アプリ内のFacebook情報を再確認

        正しいテストアカウントでログインしているか確認

        public環境の場合:

        Facebookでprofile権限が付与されているか確認 -> 付与されていなければ **Đấm Trưởng Phòng** がFacebookにプロジェクトの権限を申請

    5. appsflyerへのイベント送信確認

        タグをappsflyerに設定してログを開き、送信時にpackage nameが存在しないというエラーが出た場合は **Đấm Trưởng Phòng**

    6. 支払いの確認

        支払いを可能にするには、内部テスト版をアップロードした後、storeとhubでチャージパッケージを設定する必要がある

        支払いができない場合は不明なエラーが表示される

        apkが正しいチャージパッケージ名を送信しているか確認。

        ゲーム側が正しいチャージパッケージ名を送信しているにもかかわらずBE APIが不明なエラーを返す場合

        **Đấm Trưởng Phòng** で部門責任者からPayment側にproduction環境での有効化とGoogle Cloud上のサービス有効化設定を依頼してもらう。

        この設定を有効化するには最大1日かかり、それまで支払いはできない

## Storeでの設定

1. アプリケーションの登録

    package name登録のレビューに48時間かかるため、登録は早急に行う必要がある。

    サンプルプロジェクトが完成したら、以下のパスにファイルを作成

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image12.png)

    package name登録時にstoreから取得したコードを使用

    正しいkeystoreを使用してapkをビルドし、storeにアップロードしてpackage nameを登録

    package nameの登録後に初めて、そのアプリケーションをstore上で作成できる
