## 1. 必要なファイル一覧

統合を始める前に、以下のファイル（VTVLiveチームが提供）をすべて準備してください。

1. `AFNetworking.xcframework`
2. `FBAEMKit.xcframework`
3. `FBSDKCoreKit_Basics.xcframework`
4. `FBSDKCoreKit.xcframework`
5. `FBSDKLoginKit.xcframework`
6. `FBSDKShareKit.xcframework`
7. `iTapSdk.xcframework`
8. `ISdkTrackier.xcframework`
9. `RecapchaSdk.xcframework`
10. `RXSwift.xcframework`
11. Google-Facebook `.plist`
12. `AppConfigDefault.plist`
13. Google-Facebook `.plist.txt`
14. `Podfile`
15. サンプルデモプロジェクト（example）
16. `.mobileprovision` ファイル

:::caution
上記のファイルが揃わない場合や、統合作業中にご質問がある場合は、サポートを受けるためVTVLiveチームまでお問い合わせください。
:::

dev環境でのテストが完了した後、production環境用の専用keyを提供いたします。

## 2. SDK統合の手順

SDKを統合するには、以下の手順を順番どおりに実施してください。

### 2.1. Frameworkとlibraryをプロジェクトに追加

- **メインプロジェクト**（target app）では、上記に列挙したlibraryに対して**Embed & Sign**モードを選択してください。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image1.png)

- **UnityFramework**（Unityでビルドしたゲームの場合）では、libraryに**Do Not Embed**モードを選択してください。これらのlibraryはすでにメインtargetでembedされているため、重複を避けるためです。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image2.png)

### 2.2. Notification Service Extensionの追加

このextensionは、SDKがpush notificationの内容（Firebaseからの画像やカスタムデータを含む）を正しく処理・表示できるようにするためのものです。

1. **Xcode**でiOSプロジェクトを開きます。
2. **File > New > Target...** に進みます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image3.png)

3. テンプレート一覧から**Notification Service Extension**を探して選択します。
4. **Next**をクリックし、target名を入力します（例: `FirebaseNotificationServiceExtension`）。その後**Finish**をクリックします。
5. Xcodeから新しいschemeを有効化するか確認された場合は、**Activate**を選択します。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image4.png)

### 2.3. Extension用のFirebase SDKのインストール

1. `Podfile`を開き、作成したextension専用の**新しいtargetを追加**します。

```Swift
source 'https://mirrors.tuna.tsinghua.edu.cn/git/CocoaPods/Specs.git'

platform :ios,'15.0'
target 'Unity-iPhone' do
  use_frameworks!
  pod 'GoogleSignIn', '7.1.0'
  pod 'Firebase', '12.0.0'
  pod 'FirebaseMessaging', '12.0.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'AppsFlyerFramework', '6.17.7'
  pod 'JWT', '2.2.0'
  pod 'TikTokBusinessSDK', '1.5.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'FirebaseCrashlytics', '12.0.0'
end
target 'UnityFramework' do
  use_frameworks!
  pod 'GoogleSignIn', '7.1.0'
  pod 'Firebase', '12.0.0'
  pod 'FirebaseMessaging', '12.0.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'AppsFlyerFramework', '6.17.2'
  pod 'JWT', '2.2.0'
  pod 'TikTokBusinessSDK', '1.5.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'FirebaseCrashlytics', '12.0.0'
end

target 'FirebaseNotificationServiceExtension' do
  use_frameworks!
 pod 'Firebase', '12.0.0'
 pod 'FirebaseMessaging', '12.0.0'
end

post_install do |lib|
    lib.pods_project.targets.each do |target|
        if target.name == 'GoogleSignIn' || target.name == 'Firebase' || target.name == 'FirebaseRemoteConfig' || target.name == 'FirebaseMessaging' || target.name == 'AppsFlyerFramework' ||  target.name == 'JWT' ||  target.name == 'TikTokBusinessSDK'
            target.build_configurations.each do |config|
                config.build_settings['BUILD_LIBRARY_FOR_DISTRIBUTION'] = 'YES'
            end
        end
        
        target.build_configurations.each do |config|
            config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = '15.0'
        end
    end
end
```

2. 以下のコマンドを実行して、dependenciesをクリーンに再インストールします。

```bash
pod cache clean --all
pod deintegrate
pod install
```

### 2.4. FirebaseNotificationServiceExtensionの設定

1. `.xcworkspace`ファイルを開きます（`.xcodeproj`は開かないでください）。
2. extensionの`NotificationService.m`ファイルの内容を以下のように編集します。

```Objective-C
#import "NotificationService.h"
@import Firebase;
@import FirebaseMessaging;
@interface NotificationService ()
@property (nonatomic, strong) void (^contentHandler)(UNNotificationContent *contentToDeliver);
@property (nonatomic, strong) UNMutableNotificationContent *bestAttemptContent;
@end
@implementation NotificationService
- (void)didReceiveNotificationRequest:(UNNotificationRequest *)request withContentHandler:(void (^)(UNNotificationContent * _Nonnull))contentHandler {
    self.contentHandler = contentHandler;
    self.bestAttemptContent = [request.content mutableCopy];
    self.bestAttemptContent.title = [NSString stringWithFormat:@"%@", self.bestAttemptContent.title];
    [[FIRMessaging extensionHelper] populateNotificationContent:self.bestAttemptContent
                                                withContentHandler:contentHandler];
}
- (void)serviceExtensionTimeWillExpire {
    [[FIRMessaging extensionHelper] populateNotificationContent:self.bestAttemptContent
                                                withContentHandler:self.contentHandler];
}
@end
```

この手順の後、Xcode上のプロジェクト構成は以下のように表示されます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image5.png)

さらに:

- Appleでのログインを有効にするには、メインtargetで**Sign in with Apple** capabilityを有効にする必要があります。
- push notificationを受け取るには、**Push Notifications** capabilityを追加し、**Background Modes**内の**Background Fetch**と**Remote Notifications**を有効にする必要があります。

### 2.6. Firebase Crashlyticsの設定

メインtargetのBuild Phasesに以下の内容で**Run Script Phase**を追加し、ビルドのたびにCrashlyticsがdebug symbol（dSYM）を自動アップロードするようにします。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image6.png)

```bash
echo "Symbols Directory"
echo "${DWARF_DSYM_FOLDER_PATH}/${DWARF_DSYM_FILE_NAME}"
#Firebase
"${PODS_ROOT}/FirebaseCrashlytics/upload-symbols" -gsp "${PROJECT_DIR}/SdkExample/GoogleService-Info.plist" -p ios "${DWARF_DSYM_FOLDER_PATH}/${DWARF_DSYM_FILE_NAME}"
```

:::note
上記の例にあるパス`${PROJECT_DIR}/SdkExample/GoogleService-Info.plist`は、あくまで私たちのサンプルプロジェクト構成に対応したものです。あなたのプロジェクト内の`GoogleService-Info.plist`ファイルの実際の場所を正しく指すよう、このパスを修正してください。
:::

## 3. SDK関数の統合

このセクションでは、コード内でSDKの主要な関数を呼び出す方法を、実際の利用ライフサイクル順（初期化 → ログイン → ゲーム内の各操作 → ログアウト）に沿って説明します。

### 3.1. SDKの初期化

`AppDelegate.h`ファイルでSDKをimportし、`AppDelegate`が`SdkDelegate`プロトコルに準拠するよう宣言します。

```Objective-C
#import <UIKit/UIKit.h>
#import <iTapSdk/iTapSdk.h>
@interface AppDelegate : UIResponder <UIApplicationDelegate,SdkDelegate>

@property (strong, nonatomic) UIWindow *window;
@end
```

`AppDelegate.m`ファイルで、アプリ起動時に直ちにSDKを初期化します。

```Objective-C
- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    [[Sdk sharedInstance] initWithDelegate:self application:application launchOptions:launchOptions isProdEnv:TRUE];
    [[Sdk sharedInstance] setLocationFloatingButton:20 with:100];
    [[Sdk sharedInstance] setGrantEnv:YES];
    return YES;
}
```

- 統合・テスト中は、dev環境で実行するために`isProdEnv`を`FALSE`に変更してください。

```Objective-C
[[Sdk sharedInstance] initWithDelegate:self application:application launchOptions:launchOptions isProdEnv:FALSE];
```

- `setGrantEnv:YES` — ゲーム開始時に権限確認（広告、トラッキングなど）のpopupを表示します。このpopupを表示したくない場合は`setGrantEnv:NO`を設定してください。

### 3.2. ログイン（Login）

**ゲーム開始前に**必ず`login`関数を呼び出してください。ユーザーが初めてゲームに入る場合、SDKは自動的にログインdialogを表示し、以前にログイン済みの場合は自動でtokenをrefreshします。ログインフローの詳細については、以下の[Flowchartのセクション](#6-sơ-đồ-luồng-flowchart)を参照してください。

```Objective-C
[[Sdk sharedInstance] login];
```

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image7.png)

すべてが成功すると、上図のようにログインdialogが表示されます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image8.png)

ユーザーのログインが成功すると、登録した`SdkDelegate`の`loginSuccess`関数を通じてユーザー情報が返されます。

### 3.3. ログアウト（Logout）

```Objective-C
[[Sdk sharedInstance] logout];
```

ログアウトが成功すると、SDKはゲームに通知するため`SdkDelegate`の`logout`関数を呼び出します。

### 3.4. 商品リストの取得（List products）

store（App Store）から商品（課金パッケージ）リストを取得します。ユーザーが決済する際にtrackingシステムへ送信する商品価格が必要になるため、ログイン成功直後にこの関数を呼び出すことをお勧めします。

```Objective-C
-(void)loginSuccess:(User *)user withAccessToken:(NSString *)accessToken andRefreshToken:(NSString *)refreshToken{
    
    [[Sdk sharedInstance] listProducts:^(NSError *error, NSArray<IAPProduct*> * _Nullable result) {
        
    }];
    [[Sdk sharedInstance] showOrHideFloatingButton];
    
}
```

:::note
上記の例のように、`listProducts`の呼び出しは**ログイン成功後にのみ実行される**コード内に配置することをお勧めします。
:::

### 3.5. 言語の変更（Set Language）

対応するパラメータを指定して以下の関数を呼び出すことで、SDKの表示言語を変更できます。

```Objective-C
[[Sdk sharedInstance] setLanguage:@"vi"];
```

サポートされている言語コード:

| コード | 言語 |
| --- | --- |
| `vi` | ベトナム語 |
| `en` | 英語 |
| `th` | タイ語 |
| `zh` | 中国語 |

SDKは、言語が変更されるたびにゲームへ通知する`getLangaugeSdk` delegateも提供しています。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image9.png)

### 3.6. カウントダウンの表示（Show countdown）

以下の図のようなカウントダウン画面を表示するには、`AppDelegate`の`loginSuccess`コールバック内で、**ログイン完了後**に`showCountdown`を呼び出します。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image10.png)

```Objective-C
-(void)loginSuccess:(User *)user withAccessToken:(NSString *)accessToken andRefreshToken:(NSString *)refreshToken{

    [[Sdk sharedInstance] listProducts:^(NSError *error, NSArray<IAPProduct*> * _Nullable result) {

    }];
    [[Sdk sharedInstance] showOrHideFloatingButton];
    [[Sdk sharedInstance] showCountdown];

}
```

### 3.7. ギフトの受け取り（Receive Gift）

ユーザーがギフトボックス（gift box）ボタンを押したら、以下の関数を呼び出します。

```Objective-C
[[Sdk sharedInstance] showReceiveGift:@"1111111" withCharacterId:@"11112"];
```

- `serverId`: サーバーのId。
- `characterId`: キャラクター（character）のId。

### 3.8. 決済（Make payment）

```Objective-C
[[Sdk sharedInstance] payProduct:itemProduct.productId forCharacterId:@"17782088632480" onServerId:@"s6003"];
```

- `itemProduct.productId`: [3.4節](#34-lấy-danh-sách-sản-phẩm-list-products)の`listProducts`の結果から取得します。
- `forCharacterId`: ゲーム内のキャラクターId。
- `onServerId`: サーバーId。

決済結果（成功または失敗）は、登録した`SdkDelegate`の`didPurchaseSuccess`または`didPurchaseFailed`関数を通じてそれぞれ返されます。

### 3.9. floating buttonの表示/非表示（Show dashboard）

```Objective-C
[[Sdk sharedInstance] showOrHideFloatingButton];
```

### 3.10. キャラクター情報のマッピング（Map User）

ユーザーの現在のキャラクター情報をSDKに送信するためにこの関数を呼び出します。トラッキングやキャラクター/サーバーに関連する機能で使用されます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image11.png)

```Objective-C
-(void) mappingUser:(NSString*)characterName
        characterId:(NSString*)characterId
     characterLevel:(NSString*)characterLevel
        serverName:(NSString*)serverName
          serverId:(NSString*)serverId;

// 例:
[[SdkTracking sharedInstance] mappingUser: @"name" characterId : @1 characterLevel : @1 serverName : @"test" serverId : @"1"];
```

- `characterName`: キャラクター名。
- `characterId`: キャラクターのId。
- `characterLevel`: キャラクターの現在のレベル。
- `serverName`: サーバー名。
- `serverId`: サーバーId。

## 4. ギフトの受け取り（パラメータ不要）

SDKは、`characterId`/`serverId`を**渡す必要のない**別のオーバーロード版のギフト受け取り関数も提供しています。これは、事前に[3.10節](#310-ánh-xạ-thông-tin-nhân-vật-map-user)で`mappingUser`を呼び出している場合に使用します。この場合、SDKはすでに現在のキャラクター/サーバー情報を把握しています。

ユーザーがギフトボックスボタンを押したら、以下を呼び出します。

```Objective-C
[[Sdk sharedInstance] showReceiveGift];
```

## 5. トラッキングログ記録関数（Log Function）

以下の関数は、システムへトラッキングイベントを送信するために使用され、アプリ起動からpatchのダウンロード、キャラクター作成、ゲーム参加まで、ゲームプレイの全ライフサイクルにわたるユーザー行動の計測に役立ちます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image13.png)

上図の色の凡例:

- **灰色**: ゲーム側の処理ステップ。
- **黄色**: ゲームがSDKの関数を呼び出す必要があるポイント。

以下のログ関数をゲームのフロー内のどこに配置すべきか、正確な位置については[Flowchart](#6-sơ-đồ-luồng-flowchart)の「Login or Start Game」セクションも参照してください。

```Objective-C
-(void) logStartGameScreen;
-(void) logEnterGamePlay;
-(void) logStartTutorial;
-(void) logCompleteTutorial;
```

#### `logEnterGamePlay`

「Enter Game」ボタンを押した直後、ユーザーがgameplay画面に入ったことをトラッキングします。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image14.png)

#### `logPatchStart` — リソース（patch）のダウンロード開始

```Objective-C
-(void) logPatchStart: (NSNumber * _Nullable) sizeMB withVerrsion:(NSString * _Nullable)version withNetworkType: (NSString * _Nullable) networkType;

// sizeMB  : ダウンロードが必要なpatchファイルの容量（MB単位）
// version : インストールパッケージのバージョン

// 例:
[[SdkTracking sharedInstance] logPatchStart: @"500" withVerrsion : @"1.0.1" withNetworkType : @"wifi"];
```

#### `logPatchSuccess` — リソースのダウンロード完了

```Objective-C
-(void) logPatchSuccess: (NSNumber * _Nullable) durationSec withAvgSpeedKbps: (NSNumber * _Nullable) avgSpeedKbps withCdnNode :(NSString * _Nullable) cdnNode;

// durationSec  : ダウンロード開始からダウンロード完了までの時間（秒）
// avgSpeedKbps : 平均ダウンロード速度（Kbps）
// cdnNode      : ダウンロードに使用したCDNノード

// 例:
[[SdkTracking sharedInstance] logPatchSuccess: @"500" withAvgSpeedKbps : @"111" avgSpeedKbps : @"450" withCdnNode: @"192.168.0.2"];
```

#### `logPatchError` — リソースのダウンロード失敗

リソースのダウンロードが中断または失敗した場合に呼び出します。

```Objective-C
-(void) logPatchError:(NSString * _Nullable) errorCode withRetryCount:(NSNumber * _Nullable) retryCount withFailedUrl:(NSString * _Nullable) failedUrl withCdnNode :(NSString * _Nullable) cdnNode;

// errorCode   : エラーコード
// retryCount  : エラーによるリトライ回数
// failedUrl   : ダウンロードに失敗したURL
// cdnNode     : エラーが発生したCDNノード

// 例:
[[SdkTracking sharedInstance] logPatchError: @"500" withRetryCount: @1 withFailedUrl: @"https://cdn.game.com/patch/v120.zip" withCdnNode : @"192.168.0.2"];
```

#### `logExtractStarted` — リソースの解凍開始

ダウンロード完了直後、解凍/インストールを開始する際に呼び出します。

```Objective-C
-(void) logExtractStarted:(NSString * _Nullable) totalSizeMb withTotalSize: (NSString * _Nullable) totalSize;

// totalSizeMb : 解凍後の容量（MB単位）
// totalSize   : 解凍が必要なpatch内のファイル数（取得できない場合はスキップ）

// 例:
[[SdkTracking sharedInstance] logExtractStarted: @"500" withTotalSize : @"400"];
```

#### `logExtractFinished` — 解凍完了

解凍が完了し、ログイン画面に進む準備が整った時に呼び出します。

```Objective-C
-(void) logExtractFinished:(NSNumber * _Nullable) durationSec withResultCode:(NSString * _Nullable) resultCode;

// durationSec : 解凍開始から完了までの時間（秒）
// resultCode  : 結果コード — 0: OK、1: Disk Full（容量不足）

// 例:
[[SdkTracking sharedInstance] logExtractFinished: @100 withResultCode : @"ok"];
```

#### `logCharCreateStart` — キャラクター作成開始

```Objective-C
-(void) logCharCreateStart: (NSString * _Nullable) serverId;

// serverId : サーバーid

// 例:
[[SdkTracking sharedInstance] logCharCreateStart: @"100"];
```

:::note
キャラクター作成開始から完了までの時間を自動計測する内部timerを設定しておくことをお勧めします。この値は以下の`logCharCreateSuccess`に渡す必要があります。
:::

#### `logCharCreateSuccess` — キャラクター作成成功

```Objective-C
-(void) logCharCreateSuccess: (NSString * _Nullable) serverId withCharId:(NSString * _Nullable) charId withCharName:(NSString * _Nullable) charName withCharClass:(NSString * _Nullable) charClass withDurationSec: (NSNumber * _Nullable) durationSec;

// serverId    : サーバーid
// charId      : キャラクターid
// charName    : キャラクター名
// charClass   : キャラクタークラスid（class_id）
// durationSec : 作成開始から成功までの時間（秒）

// 例:
[[SdkTracking sharedInstance] logCharCreateSuccess: @"500" withVerrsion : @"1.0.1" withNetworkType : @"wifi"];
```

:::danger[例に誤りがある可能性]
上記の例の行は元のドキュメントのまま保持していますが、パラメータ`withVerrsion`/`withNetworkType`は、上で宣言されている`logCharCreateSuccess`関数のシグネチャと一致していません（おそらく`logPatchStart`の例から誤ってコピーされたものと思われます）。使用前にSDK開発チームへ正しいパラメータを確認してください。
:::

#### `logCharCreateError` — キャラクター作成失敗

```Objective-C
-(void) logCharCreateError:(NSString * _Nullable) errorCode withCharName:(NSString * _Nullable) charName withServerId:(NSString * _Nullable) serverId;

// errorCode : エラーコード
// charName  : キャラクター名
// serverId  : サーバーid

// 例:
[[SdkTracking sharedInstance] logCharCreateError: @"NAME_DUPLICATED" withCharName : @"test" withServerId :@"1"];
```

#### `logCharSelect` — キャラクター選択

ユーザーがサーバーとキャラクターを選択してゲームに入る直後にこの関数を呼び出します。

```Objective-C
-(void) logCharSelect: (NSString * _Nullable) charId withCharacterName :(NSString* _Nonnull) characterName withCharLevel:(NSString * _Nullable) charLevel;

// charId        : キャラクターid
// characterName : キャラクター名
// charLevel     : キャラクターレベル

// 例:
[[SdkTracking sharedInstance] logCharSelect: @"1" withCharacterName : @"name " withCharLevel : @"1"];
```

## 6. 決議147号に基づく情報同期の更新

```Objective-C
dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
    BOOL needShow = [[Sdk sharedInstance] isNeedShowEventProfileSync];
    if (needShow) {
        dispatch_async(dispatch_get_main_queue(), ^{
            [[Sdk sharedInstance] showEventProfile];   // showEventProfile cần chạy trên main thread vì có UI
        });
    }
});
```

- `isNeedShowEventProfile()`が`true`を返す場合: 情報同期画面（Event Profile）を開き、ユーザーに情報を更新させます。
- `isNeedShowEventProfile()`が`false`を返す場合: この画面を表示せずに、ユーザーを直接ゲームに入らせます。

### App Storeへのアップロード用IPAファイルのエクスポート方法

:::danger[要照合]
元のドキュメントにはこれらの手順のスクリーンショットのみが記載されており、文章による説明は付いていません。以下の7つの手順は、ドキュメントチームがXcodeの標準的なarchive/exportプロセスに基づいて作成した説明です。実際に従う前に、以下の実際のスクリーンショットと照合し、一致しない手順があればご報告ください。
:::

Xcodeで以下の手順に従ってください。

1. ビルド先をsimulatorではなく**Any iOS Device (arm64)**に選択します。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image23.png)

2. **Product > Archive**メニューに進み、Xcodeにarchiveをビルド・パッケージ化させます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image24.png)

3. archiveが完了すると、**Organizer**ウィンドウが自動で開き、作成したarchiveが表示されます。**Distribute App**を選択します。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image25.png)

4. 適切な配布方法（例: **App Store Connect**または**Ad Hoc**）を選択し、Xcodeのウィザードの手順に従います。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image26.png)

5. エクスポート前に、entitlements内の**aps-environment**が（`development`ではなく）`production`になっていることを必ず確認してください。そうでない場合、リリース版でpush notificationが動作しません。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image27.png)

6. エクスポートが完了したら、**Show in Finder**を選択して`.ipa`ファイルが入ったフォルダを開きます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image28.png)

7. `.ipa`ファイル（または`.xcarchive`ファイル）を右クリックし、**Show Package Contents**を選択すると、debug symbolの送付が必要な場合に内部のdSYMファイルを取得できます。

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image29.png)

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image30.png)

:::note
デバッグのサポートが必要な場合は、対応する**dSYM**ファイルと**.ipa**ファイルの両方をVTVLiveチームまでお送りください。
:::
