## 1. 必要なファイル一覧

統合を始める前に、以下のファイル一式を準備しておく必要があります（VTVLive チームより提供）。

1. `AFNetworking.xcframework`
2. `iTapSdk.xcframework`
3. `ISdkTrackier.xcframework`
4. Google-Facebook `.plist`
5. `AppConfigDefault.plist`
6. Google-Facebook `.plist.txt`
7. サンプルのデモプロジェクト（example）
8. `.mobileprovision` ファイル

:::caution
上記のファイルが不足している場合、または統合中に何かご不明な点がございましたら、VTVLive チームまでお問い合わせください。
:::

dev 環境でのテストが完了した後、本番（production）環境用の専用キーをご提供いたします。

## 2. SDK 統合手順

SDK を統合するには、以下の手順を正しい順序で行ってください。

### 2.1. framework とライブラリをプロジェクトに追加

- **メインプロジェクト**（target app）では、上記に列挙したライブラリに対して **Embed & Sign** モードを選択してください。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image1.png)

- **UnityFramework**（Unity でビルドされたゲームの場合）では、これらのライブラリに対して **Do Not Embed** モードを選択してください。ライブラリはすでにメインターゲットに embed されているため、重複を避ける必要があります。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image2.png)

### 2.2. Notification Service Extension の追加

このエクステンションは、SDK が push notification の内容（Firebase からの画像やカスタムデータを含む）を正しく処理・表示するのを助けます。

1. **Xcode** で iOS プロジェクトを開きます。
2. **File > New > Target...** を選択します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image3.png)

3. テンプレート一覧から **Notification Service Extension** を探して選択します。
4. **Next** を押し、ターゲット名（例: `FirebaseNotificationServiceExtension`）を入力してから **Finish** を押します。
5. Xcode が新しいスキームを有効化するか確認してきたら、**Activate** を選択します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image4.png)

### 2.3. パッケージ依存関係の追加

必要なパッケージ（例: Firebase）を **Swift Package Manager** 経由でプロジェクトに追加します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image5.png)

### 2.4. FirebaseNotificationServiceExtension の設定

エクステンションの `NotificationService.swift` ファイルを開き、以下のように内容を編集します。

```swift
import UserNotifications
import Firebase
import FirebaseMessaging

class NotificationService: UNNotificationServiceExtension {

    var contentHandler: ((UNNotificationContent) -> Void)?
    var bestAttemptContent: UNMutableNotificationContent?

    override func didReceive(_ request: UNNotificationRequest, withContentHandler contentHandler: @escaping (UNNotificationContent) -> Void) {
        self.contentHandler = contentHandler
        bestAttemptContent = (request.content.mutableCopy() as? UNMutableNotificationContent)

        if let bestAttemptContent = bestAttemptContent {
            FIRMessaging.extensionHelper().populateNotificationContent(bestAttemptContent, withContentHandler: contentHandler)
        }
    }

    override func serviceExtensionTimeWillExpire() {
        if let contentHandler = contentHandler, let bestAttemptContent = bestAttemptContent {
            contentHandler(bestAttemptContent)
        }
    }
}
```

この手順の後、Xcode 上のプロジェクト構造は以下の図のように表示されます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image6.png)

その他:

- Apple でのログインを有効にするには、メインターゲットで **Sign in with Apple** capability を有効にする必要があります。
- push notification を受け取るには、**Push Notifications** capability を追加し、**Background Modes** 内で **Background Fetch** と **Remote Notifications** を有効にする必要があります。

## 3. SDK 関数の統合

SDK は、主要機能全体を扱うシングルトン `Sdk.sharedInstance` と、イベントトラッキング関数専用のシングルトン `SdkTracking.shared` を提供します。このセクションでは、初期化 → ログイン → ゲーム内の各操作 → ログアウトという実際の利用ライフサイクルの順にご案内します。

### 3.1. SDK の初期化

`AppDelegate.swift` で SDK を import し、`AppDelegate` が `SdkDelegate` プロトコルに準拠するよう宣言し、アプリ起動直後に SDK を初期化します。

```swift
import UIKit
import iTapSdk

@main
class AppDelegate: UIResponder, UIApplicationDelegate, SdkDelegate {

    func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        Sdk.sharedInstance.initWithDelegate(self, application: application, launchOptions: launchOptions, environment: .prod)
        Sdk.sharedInstance.setLocationFloatingButton(width: 20, height: 100)
        return true
    }

    // 必須: Facebook / Google Sign-In の URL コールバックを転送
    func application(_ application: UIApplication, open url: URL, options: [UIApplication.OpenURLOptionsKey: Any] = [:]) -> Bool {
        return Sdk.sharedInstance.application(application, open: url, options: options)
    }
}
```

- 統合・テスト中は、`environment` を `.dev` に切り替えてください。

```swift
Sdk.sharedInstance.initWithDelegate(self, application: application, launchOptions: launchOptions, environment: .dev)
```

`AppDelegate` の extension 内に、`SdkDelegate` の各コールバック（すべて optional のため、必要なものだけ実装してください）を実装します。

```swift
extension AppDelegate {

    func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
        // ログイン成功 — user.accountID、user.accountName
    }

    func sdk(_ sdk: Sdk, logout user: User) {
        // ログアウト成功
    }

    func sdk(_ sdk: Sdk, didPurchaseSuccess transactionInfo: TransactionInfo) {
        // 決済成功 — transactionInfo.productId、transactionInfo.transId...
    }

    func sdk(_ sdk: Sdk, didPurchaseFailed transactionInfo: TransactionInfo, purchaseError: String?) {
        // 決済失敗
    }

    func sdk(_ sdk: Sdk, getLanguage language: String) {
        // SDK の言語が変更された
    }

    func sdkCloseLoginView() {
        // ログイン画面が閉じられた
    }
}
```

:::note
Swift 版 SDK は、初期化時に権限リクエスト（通知、App Tracking Transparency）を自動的に処理します。旧 Objective-C 版のような、権限ポップアップを手動でオン/オフする関数はありません。
:::

### 3.2. ログイン（Login）

**ゲームが開始する前に** 必ず `login()` を呼び出してください。ユーザーが初めてゲームに入る場合、SDK が自動的にログインダイアログを表示します。既にログイン済みの場合は、自動的にトークンをリフレッシュします。

```swift
Sdk.sharedInstance.login()
```

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image8.png)

すべて正常であれば、上図のようにログインダイアログが表示されます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image9.png)

ユーザーのログインが成功すると、あらかじめ SDK に登録しておいた `SdkDelegate` の `sdk(_:loginSuccess:accessToken:refreshToken:)` コールバック経由でユーザー情報が返されます。

### 3.3. ログアウト（Logout）

```swift
Sdk.sharedInstance.logout()
```

ログアウトが成功すると、SDK はゲームに通知するために `sdk(_:logout:)` コールバックを呼び出します。また、`Sdk.sharedInstance.forceLogout()` もあります。これはサーバー側の refresh token 破棄 API を呼び出さずに即座にログアウトするもので、サーバー側でログインセッションが既に期限切れになっている場合に使用します。

### 3.4. 商品一覧の取得（List products）

App Store から商品（課金パッケージ）の一覧を取得します。決済時にトラッキングシステムへ商品価格を送信する必要があるため、この関数はログイン成功直後に呼び出すことを推奨します。

```swift
func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
    Sdk.sharedInstance.listProducts { error, products in
        // products: [IAPProduct]?
    }
    Sdk.sharedInstance.showOrHideFloatingButton()
}
```

:::note
上記の例のように、`listProducts` の呼び出しは `loginSuccess` コールバック内に配置することを推奨します。それ以上待つ必要はありません。
:::

### 3.5. 言語の変更（Set Language）

SDK の表示言語を変更するには、以下の関数を呼び出してください。

```swift
Sdk.sharedInstance.setLanguage(input: "vi")
```

サポートされている言語コード:

| コード | 言語 |
| --- | --- |
| `vi` | ベトナム語 |
| `en` | 英語 |
| `th` | タイ語 |
| `zh` | 中国語 |

SDK は、言語が変更されるたび（初回初期化時も含む）に `SdkDelegate` の `sdk(_:getLanguage:)` コールバックを呼び出します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image10.png)

### 3.6. カウントダウンの表示（Show countdown）

下図のようなカウントダウン UI を表示するには、**ログイン完了後に** `showCountdown()` を呼び出してください。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image11.png)

```swift
func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
    Sdk.sharedInstance.listProducts { error, products in }
    Sdk.sharedInstance.showOrHideFloatingButton()
    Sdk.sharedInstance.showCountdown()
}
```

`Sdk.sharedInstance.isCountdownAvailable() -> Bool` を使うことで、カウントダウンイベントが利用可能かどうかを事前に確認できます。

### 3.7. ギフト受け取り（Receive Gift）

```swift
Sdk.sharedInstance.showReceiveGift()
```

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image13.png)

:::note
この関数はパラメータを受け取りません。SDK は、直近に呼び出された `mappingUser(...)`（[3.10 節](#310-キャラクター情報のマッピングmap-user)）から保存された `characterId`/`serverId` を自動的に取得します。そのため、ギフト受け取りボタンを表示する前に `mappingUser` を呼び出しておく必要があります。
:::

### 3.8. 決済（Make payment）

```swift
Sdk.sharedInstance.payProduct(itemProduct.productId ?? "", forCharacterId: "17782088632480", onServerId: "s6003")
```

- 第一引数（`productID`）: [3.4 節](#34-商品一覧の取得list-products)の `listProducts` の結果に含まれる `IAPProduct` の `productId` を使用します。
- `forCharacterId`: ゲーム内のキャラクター Id。
- `onServerId`: サーバー Id。

決済結果（成功または失敗）は、それぞれ `SdkDelegate` の `sdk(_:didPurchaseSuccess:)` または `sdk(_:didPurchaseFailed:purchaseError:)` コールバック経由で返されます。

### 3.9. フローティングボタンの表示/非表示（Show dashboard）

```swift
Sdk.sharedInstance.showOrHideFloatingButton()
```

### 3.10. キャラクター情報のマッピング（Map User）

ユーザーの現在のキャラクター情報を SDK に送信するために、この関数を呼び出します。トラッキングや、[3.7 節](#37-ギフト受け取りreceive-gift)の `showReceiveGift()` を含む、キャラクター/サーバーに関連する各機能に使用されます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image12.png)

```swift
Sdk.sharedInstance.mappingUser(
    "name",
    characterId: "1",
    characterLevel: "1",
    serverName: "test",
    serverId: "1"
)
```

- 第一引数（ラベルなし）: キャラクター名。
- `characterId`: キャラクターの Id。
- `characterLevel`: キャラクターの現在のレベル。
- `serverName`: サーバー名。
- `serverId`: サーバー Id。

SDK にはさらに `Sdk.sharedInstance.levelUpUser(_:characterId:characterLevel:serverName:serverId:vip:)` があります。キャラクターがレベルアップまたは VIP がアップした際に呼び出すことで、トラッキングシステムが達成したマイルストーンを記録します。

## 4. トラッキングログ関数（SdkTracking）

以下の関数は（`Sdk.sharedInstance` とは異なる）シングルトン **`SdkTracking.shared`** 上にあり、システムにトラッキングイベントを送信するために使用します。アプリを開く、パッチのダウンロード、キャラクター作成からゲームに入るまで、ゲームプレイのライフサイクル全体にわたるユーザー行動を計測するのに役立ちます。

元のフローチャートにおける色の凡例:

- **グレー**: ゲーム側で処理されるステップ。
- **黄色**: ゲームが SDK の関数を呼び出す必要があるポイント。

これらのログ関数をゲームの実行フローのどこに正確に配置すべきかについては、[フローチャート](#6-フローチャートflowchart)の「Login or Start Game」の項もあわせてご参照ください。

```swift
SdkTracking.shared.logStartGameScreen()
SdkTracking.shared.logEnterGamePlay()
SdkTracking.shared.logStartTutorial()
SdkTracking.shared.logCompleteTutorial()
```

#### `logEnterGamePlay()`

「Enter Game」ボタンを押した直後、ユーザーがゲームプレイ画面に入ったイベントをトラッキングします。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image14.png)

#### `logPatchStart` — リソース（パッチ）のダウンロード開始

```swift
SdkTracking.shared.logPatchStart(sizeMB: 500, withVerrsion: "1.0.1", withNetworkType: "wifi")
```

| パラメータ | 意味 |
| --- | --- |
| `sizeMB` | ダウンロードが必要なパッチファイルの容量（MB） |
| `withVerrsion` | インストールパッケージのバージョン |
| `withNetworkType` | ネットワークの種類（`"wifi"`、`"4g"`など） |

#### `logPatchSuccess` — リソースのダウンロード完了

```swift
SdkTracking.shared.logPatchSuccess(durationSec: 450, withAvgSpeedKbps: 111, withCdnNode: "192.168.0.2")
```

| パラメータ | 意味 |
| --- | --- |
| `durationSec` | ダウンロード開始からダウンロード完了までの時間（秒） |
| `withAvgSpeedKbps` | 平均ダウンロード速度（Kbps） |
| `withCdnNode` | ダウンロードに使用した CDN ノード |

#### `logPatchError` — リソースのダウンロード失敗

```swift
SdkTracking.shared.logPatchError(errorCode: "500", withRetryCount: 1, withFailedUrl: "https://cdn.game.com/patch/v120.zip", withCdnNode: "192.168.0.2")
```

| パラメータ | 意味 |
| --- | --- |
| `errorCode` | エラーコード |
| `withRetryCount` | エラーによるリトライ回数 |
| `withFailedUrl` | ダウンロードに失敗した URL |
| `withCdnNode` | エラーが発生した CDN ノード |

#### `logExtractStarted` — リソースの解凍開始

```swift
SdkTracking.shared.logExtractStarted(totalSizeMb: "500", withTotalSize: "400")
```

| パラメータ | 意味 |
| --- | --- |
| `totalSizeMb` | 解凍後の容量（MB） |
| `withTotalSize` | パッチ内で解凍が必要なファイル数 |

#### `logExtractFinished` — 解凍完了

```swift
SdkTracking.shared.logExtractFinished(durationSec: 100, withResultCode: "ok")
```

| パラメータ | 意味 |
| --- | --- |
| `durationSec` | 解凍開始から完了までの時間（秒） |
| `withResultCode` | 結果コード — `"ok"`/`0`: OK、`1`: Disk Full |

#### `logCharCreateStart` — キャラクター作成開始

```swift
SdkTracking.shared.logCharCreateStart(serverId: "100")
```

:::note
作成開始から完了までの時間を自動計測する内部タイマーを設定することを推奨します。この値は下記の `logCharCreateSuccess` に渡す必要があります。
:::

#### `logCharCreateSuccess` — キャラクター作成成功

```swift
SdkTracking.shared.logCharCreateSuccess(
    serverId: "100",
    withCharId: "1001",
    withCharName: "test",
    withCharClass: "1",
    withDurationSec: 5
)
```

| パラメータ | 意味 |
| --- | --- |
| `serverId` | サーバー Id |
| `withCharId` | キャラクター Id |
| `withCharName` | キャラクター名 |
| `withCharClass` | キャラクターのクラス Id（class_id） |
| `withDurationSec` | 作成開始から作成成功までの時間（秒） |

#### `logCharCreateError` — キャラクター作成失敗

```swift
SdkTracking.shared.logCharCreateError(errorCode: "NAME_DUPLICATED", withCharName: "test", withServerId: "1")
```

#### `logCharSelect` — キャラクター選択

ユーザーがサーバーとキャラクターを選択してゲームに入った直後にこの関数を呼び出してください。

```swift
SdkTracking.shared.logCharSelect("1", withCharacterName: "name", withCharLevel: "1")
```

## 5. Nghị định（政令）147 に基づく情報同期のアップデート

旧 Objective-C 版（`isNeedShowEventProfileSync` と `showEventProfile` の 2 つの関数を手動で呼び出す方式）とは異なり、Swift 版では**単一の関数** `checkShow147` に統合されており、必要な場合は SDK が**自動的に画面を表示**します。呼び出すだけで、（任意で）completion 経由で結果を読み取ることができます。

```swift
Sdk.sharedInstance.checkShow147 { needVerify in
    // needVerify == true: SDK が情報同期画面（Event Profile）を自動的に開いた
    // needVerify == false: これ以上何もする必要はなく、ユーザーをゲームに入らせてよい
}
```

`loginSuccess` コールバック内で、ゲームのメイン画面に入る前に呼び出すことを推奨します。

## 7. SDK 内の主要なクラス/データ型

**`IAPProduct`** — 商品（課金パッケージ）1 件の情報:

| プロパティ | 説明 |
| --- | --- |
| `productId` | 商品 Id。App Store 上で宣言された商品 id と一致 |
| `productDescription` | 商品の説明 |
| `localizedPrice` | 端末のロケールに応じて表示される商品価格 |
| `price` / `currencyCode` / `priceLocale` | 元の価格、通貨コード、ロケール（価格を自前でフォーマットする必要がある場合に使用） |
| `appAmount` | このパッケージ購入時にユーザーが受け取る gold（ゴールド）の数量 |
| `amount` | 対応する vXu の数量 |

**`User`** — ユーザー情報:

| プロパティ | 説明 |
| --- | --- |
| `accountID` | ユーザーアカウントの Id |
| `accountName` | アカウントのユーザー名 |

**`TransactionInfo`** — 決済の取引情報（`didPurchaseSuccess`/`didPurchaseFailed` 経由で返される）:

| プロパティ | 説明 |
| --- | --- |
| `transId` | 取引 Id |
| `productId` | 購入した商品の Id |
| `purchasedToken` | App Store からの取引確認トークン |
| `paymentOrderId` | 決済システム側の注文 Id |
| `confirmByServer` | サーバー側からの確認状態 |

**`Sdk`** — SDK のメインシングルトン:

| 要素 | 説明 |
| --- | --- |
| `Sdk.sharedInstance` | SDK のシングルトン |
| `delegate: SdkDelegate?` | 各種コールバック（ログイン、ログアウト、決済など）を受け取る場所 |
| `environment: Environment` | `.prod` または `.dev` |
| `getCurrentAccessToken() -> String` | ログイン成功後の現在の access token を取得 |

## 9. Keychain への証明書のインポートと IPA のビルド

`.ipa` ファイルのビルドに必要な証明書（`apn_certificate`、`dev_certificate`、`dis_certificate`、development provisioning profile、production provisioning profile を含む）をご提供いたします。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image18.png)

**手順 1 — 証明書を Keychain にインポート:** `.p12` ファイルをダブルクリック（またはドラッグ＆ドロップ）して Keychain Access に追加します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image19.png)

インポートに成功すると、下図のように Keychain 内に証明書が表示されます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image20.png)

**手順 2 — provisioning profile を Xcode にインポート:** provisioning profile ファイルをダブルクリック（または Xcode にドラッグ＆ドロップ）すると、Xcode が自動的に認識します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image21.png)

:::caution[Client ID / Client Secret の誤り]
Client ID または Client Secret の設定が誤っている場合、下図のような署名（code signing）エラーが表示されます。**Signing & Capabilities** で設定を確認し、インポートした provisioning profile に対応する正しい **Code Sign Identity** を選択してください。

IPA ファイルのビルド時に provisioning 関連のエラーが引き続き発生する場合は、その provisioning profile を作成する際に使用した bundle id、team、証明書を再度よくご確認ください。
:::

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image22.png)

### App Store にアップロードするための IPA ファイルのエクスポート方法

:::danger[要照合]
元のドキュメントには、これらの手順に対するスクリーンショットのみが含まれており、文章による説明はありませんでした。以下の 7 つの手順の内容は、ドキュメントチームが Xcode 標準の archive/export の手順に沿って解釈し直したものです。実際に手順を進める前に、下記の実際のスクリーンショットと照らし合わせてご確認いただき、一致しない箇所があればご報告ください。
:::

Xcode で以下の手順に従ってください。

1. ビルド先をシミュレーターではなく **Any iOS Device (arm64)** に設定します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image23.jpg)

2. **Product > Archive** メニューを選択し、Xcode に archive をビルド・パッケージ化させます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image24.jpg)

3. archive が完了すると **Organizer** ウィンドウが自動的に開き、作成された archive が表示されます。**Distribute App** を選択します。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image25.jpg)

4. 適切な配布方法（例: **App Store Connect** または **Ad Hoc**）を選択し、Xcode のウィザードの手順に従います。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image26.jpg)

5. エクスポート前に、entitlements 内の **aps-environment** が `development` ではなく `production` になっていることを必ず確認してください。そうでない場合、リリース版で push notification が動作しません。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image27.png)

6. エクスポートが完了したら、**Show in Finder** を選択して `.ipa` ファイルが格納されたフォルダを開きます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image28.png)

7. `.ipa` ファイル（または `.xcarchive` ファイル）を右クリックし、**Show Package Contents** を選択すると、debug symbol の送付が必要な場合に内部の dSYM ファイルを取得できます。

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image29.png)

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image30.png)

:::note
デバッグのサポートが必要な場合は、対応する **dSYM** ファイルと **.ipa** ファイルの両方を VTVLive チームまで送付してください。
:::
