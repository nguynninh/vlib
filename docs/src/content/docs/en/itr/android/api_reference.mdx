    }

### 1.1. Public properties

| Member | Type | Description |
|---|---|---|
| `valueTimePlay` | `Int` (read-only) | The most recent playback second the app has fed in via `receiveTrackingTime` |
| `receiveTrackingTime` | `(Int) -> Unit` | **Feeds the playback time (seconds) for a VOD stream.** Call it like a function: `overlayManager.receiveTrackingTime(12)` |

### 1.2. Methods

| Function | Description | Notes |
|---|---|---|
| `initToken(token: String, userId: String, bjName: String = "")` | Declares/clears the login session | Call before `joinRoom`. Logout: `initToken("", "")`. If a Live session is active, it automatically rejoins the room |
| `joinRoom(mediaId: String, type: Int)` | Starts an interactive session for a piece of content | `type = 1` LIVE, `type = 2` VOD. Automatically calls `cleanUp()` on the previous session |
| `releaseAll()` | Releases everything: socket, WebView, dialog, tracking | Call in `onDestroy()` or when leaving the content |
| `fetchInteractiveStatus(mediaId: String, callback: (Boolean) -> Unit)` | Asks the server whether this content is interactive | Network error → returns `false` |
| `showChartsInteractive(mediaId: String, userId: String, backgroundColorHeader: String? = null)` | Opens the leaderboard (full-screen DialogFragment) | `backgroundColorHeader` is a hex code, e.g. `"#139DED"` |
| `hideChartsInteractive()` | Closes the leaderboard | |
| `isDialogCharShowing(): Boolean` | Whether the leaderboard is currently showing | |
| `addPlayerListener(listener: PlayerChangeListener)` | Supplies the player state to the SDK (used for the `ckst` event) | Call **after** `joinRoom` so the listener is also attached to the socket |
| `sendAction(data: JSONObject)` | *(implements `OnOverlayListener`)* Handles an action from the WebView | Called automatically by the SDK, the app does **not** need to call it |
| `onClickAdsOverlay(url: String)` | *(implements `OnOverlayListener`)* Opens an ad URL in an external browser | Called automatically by the SDK |

> `LifecycleOverlay` is currently an empty interface (the `onResume/onStop/onDestroy` functions have been
> commented out in the code) — the SDK does **not** hook into the Activity lifecycle beyond observing LiveData.

  <TabItem label="Java">
```java
interface OverlayEventListener {
    void onHandleMessage(EventOverlay msg);
    void onHandleLiveViews(int liveViews);
    void onShowITR(boolean show);
    void onFocusOverlay(boolean takeControl, boolean webViewError, OverlayConfig overlayConfig);
    // defaults: takeControl = false, webViewError = false, overlayConfig = null
}

interface DefaultOverlayEventListener extends OverlayEventListener {   // alias, adds no functions
}
```
  </TabItem>
</Tabs>

| Callback | When it is called | What the app should do |
|---|---|---|
| `onHandleMessage(NEED_LOGIN)` | User interacted with the overlay in a way that requires login | Open the login screen, then call `initToken()` |
| `onHandleMessage(NEED_PAY_ONG)` | Server returned `PM402` (insufficient OnG) | Open the top-up screen |
| `onHandleLiveViews(n)` | Socket `liveviews` event | Display the viewer count (**already offset by +230**) |
| `onShowITR(true)` | The overlay opens a stats/dialog section | Hide part of the app's UI if needed |
| `onFocusOverlay(takeControl = true, …)` | WebView finished loading (`onPageFinished`) | Adjust the layout if the overlay is a popup |
| `onFocusOverlay(webViewError = true, …)` | Page load / HTTP / SSL error | Log it, optionally notify the user |
| `onFocusOverlay(takeControl = false, …)` | The overlay was removed (`INTERACTIVE_HIDE_ANALYTICS`) | Restore the layout |

`playbackState` follows the ExoPlayer convention: `1 = IDLE`, `2 = BUFFERING`, `3 = READY`, `4 = ENDED`.
The SDK maps them as: `1 → "idle"`, `3 → isPlaying ? "playing" : "paused"`, everything else → `""`.

## 5. `OverlayView`

A custom `ConstraintLayout` that acts as the **container** for every overlay.

| Public member | Description |
|---|---|
| `overlayList: HashMap<OverlayWebView, OverlayConfig>` | The WebViews currently attached |
| `addListener(eventListener, overlayListener)` | Called automatically by the SDK in `OverlayManager.init` |
| `getCurrentOrientation(): Int` | Current screen orientation |
| `getLastOverlay(): OverlayWebView?` | The most recently attached WebView |
| `getOverlayConfig(): OverlayConfig?` | Config for the popup-style overlay (if any) |
| `removeWebView(view)`, `removeWebViews()`, `clearViews()` | Removes the view(s) and cancels the corresponding tracking |

The app only needs to declare this view in XML; the remaining functions are used internally by the SDK.

## 6. Core models

### `Overlay` — describes a single overlay

| Field | Type | Meaning |
|---|---|---|
| `src` | `String` | Web template URL |
| `metadata` | `Metadata(pos, size)` | Position + size as ratios |
| `duration` | `Long` | Display duration (seconds) |
| `targets` | `String?` | Applicable platform (`all`, `androidmobile`, `androidtv`…) |
| `timelineId` | `String?` | Scenario milestone identifier (dedup / anti-double-reply key) |
| `mediaContentId` | `String?` | The content it applies to |
| `typeTimeline` | `Int?` | 0/1/2 mini game, 3 predict, 4 headline, 5 lucky |
| `isPopupOverlay` | `Boolean` | `true` → uses popup constraints based on 9 positions; `false` → inline top/bottom |
| `allowAnonymous` | `Boolean` | Whether non-logged-in users can view/interact |
| `requiredFanClub` | `Boolean?` | Requires fan club membership |
| `startTimeShowOverlay` | `Long?` | (VOD) the second at which it starts showing |
| `requiredFocus`, `frequencyLimit`, `ts`, `sendTime`, `serverTime` | | Auxiliary fields from the server |

## 7. Socket.IO events

### 7.1. Server → SDK (listened to)

| Event name | Constant | Data type | Handling |
|---|---|---|---|
| `overlay` | `Const.OVERLAY` | `JSONObject` | Realtime overlay |
| `ex-overlay` | `Const.EX_OVERLAY` | `JSONObject` | Catch-up overlay (skipped if `duration <= 10`) |
| `overlay-recall` | `Const.OVERLAY_RECALL` | `JSONObject` \| `ByteArray` | Recalls an overlay by `timelineId` |
| `predict-timeline` | `Const.PREDICT_TIMELINE` | `ByteArray` | `ACTIVE` / `INACTIVE` / `POWER` / `END` |
| `lucky-event` | `Const.LUCKY_EVENT` | `ByteArray` | `ACTIVE` / `INACTIVE` / `POWER` / `END` |
| `predict-result` | `Const.PREDICT_RESULT` | `ByteArray` | `answer1` / `answer2` figures |
| `update-result` | `Const.UPDATE_RESULT` | `ByteArray` | Pushed to the web via `UPDATE_DATA_INTERACTIVE` |
| `liveviews` | `Const.LIVE_VIEWS` | `JSONObject` | Viewer count |
| `data` | `Const.FAN_CLUB` | `ByteArray` | Fan club status |
| `ckst` | `Const.CKST` | `JSONObject` | Server asks for player status |

### 7.2. SDK → Server (emitted)

| Name | When | Payload |
|---|---|---|
| `join-room` | After the socket connects | `{deviceId, mediaContentId, os, versionSDK, tenantId, isActivelyDisconnectSocket}` |
| `leave-room` | `leaveRoom()` | Same as above |
| `receive-message` | Payload has `traceLock = true` | Original payload (UTF-8 ByteArray) |
| `emit-ack` | Tracking milestones | See [05 — Tracking](05-tracking-emit-ack.md) |
| `ckst` | Response to the `ckst` event | `{action: "CHECK_PLAYER_STATUS", sessionId, data: {deviceId, os, mediaContentId, playerStatus}}` |

### 7.3. Headers used when connecting the socket

| Header | Value |
|---|---|
| `X-TENANT-ID` | `tenantId` |
| `v` | `BuildConfig.BUILD_VERSION` (SDK build date) |
| `os` | `BuildConfig.DEVICE_TYPE` (`androidmobile` / `androidtv`) |
| `deviceId` | `Settings.Secure.ANDROID_ID` |
| `Authorization` | `Bearer <jwt>` or the raw cookie |

Connection options: uses only `websocket`, auto-reconnects, 5000ms delay (both `reconnectionDelay` and
`reconnectionDelayMax`), `randomizationFactor = 0.4`.

## 8. HTTP endpoints

Base URL = `Const.INTERACTIVE_URL` (derived from `EnvInteractive`).
The `BaseRequest` interceptor automatically adds the `X-TENANT-ID` header.

| Method | Path | Header | Used for |
|---|---|---|---|
| `GET` | `/api/ctc/scenario/v2/vod/{mediaContentId}/{os}` | `Authorization` | Loads the VOD scenario |
| `GET` | `/api/scenario/getActiveOverlay/{mediaContentId}` | — | Fetches the currently active overlay (catch-up) |
| `POST` | `/api/actions` | `Authorization` | Sends an action / reply |
| `GET` | `/api/public/vip-status` | `Authorization` | Checks VIP status before replying |
| `GET` | `/api/media/interactive-status/{mediaId}` | `x-tenant-id`, `Cookie` | Whether the content is interactive |

**`/api/actions` request body** (fields the SDK adds to the JSON sent by the web):

```jsonc
{
  "type": "INTERACTIVE_ACTION_REPORT",
  "deviceId": "<android-id>",      // added by the SDK
  "os": "(os, androidmobile)",     // added by the SDK
  "data": {
    "timelineId": "...",
    "typeTimeline": 1,
    "betAmount": 0,
    "allowAnonymous": false,
    "requiredFanClub": false,
    "media": "<mediaId>",          // added by the SDK
    "socket_id": "<socket id>"     // added by the SDK (only when Live)
    // ...other fields sent by the web template
  }
}
```

## 9. JS bridge protocol

Interface name: **`Android`** (`Const.JS_INTERFACE_NAME`).

### Web → SDK

```javascript
Android.postMessage(JSON.stringify({ key: "LOADED_OVERLAY" }));
Android.postMessage(JSON.stringify({ type: "INTERACTIVE_ACTION_REPORT", data: {...} }));
```

| Value | Constant | Meaning |
|---|---|---|
| `key = LOADED_OVERLAY` | `Const.LOADED_OVERLAY` | Template is ready to receive data |
| `type = INTERACTIVE_SHOW_ANALYTICS` | | Overlay is shown |
| `type = INTERACTIVE_HIDE_ANALYTICS` | | Overlay is closed |
| `type = INTERACTIVE_ACTION_REPORT` | | Reply / action (has `data.action = "CLICK_ADS"` for ads) |
| `type = INTERACTIVE_OPEN_ANALYTICS` | | Opens the predict/lucky dialog |
| `type = INTERACTIVE_CLOSE_ANALYTICS` | | Closes the predict/lucky dialog |

### SDK → Web

```javascript
window.addEventListener("message", (e) => { /* e.data contains key + data */ });
```

| `key` | Content |
|---|---|
| `GET_DATA_INTERACTIVE` | Initial overlay data |
| `UPDATE_DATA_INTERACTIVE` | Realtime result update |
| `UPDATE_CONFIRM` | Confirms the reply was submitted successfully |
| `UPDATE_COUTER` | Predict figures (`answer1`, `answer2`) |
| `UPDATE_NUMBER_LUCKY` | Lucky result |

## 10. Query parameters appended to the template URL

| Parameter | When it is added |
|---|---|
| `os=<deviceType>` | If `src` doesn't already have `&os` |
| `logged=false` | Not logged in **and** the overlay is not `allowAnonymous` |
| `duration=<remaining seconds>` | Always (computed from `missTime`) |
| `fanclub=false` | Overlay requires fan club but the user isn't a member |
| `u=<userId>` | Only for `PredictDialog` / `LuckyDialog` |
| `timelineId`, `tenantId`, `deviceType`, `os` | Only for VOD overlays (built in `parseTimeLineListForVOD`) |
