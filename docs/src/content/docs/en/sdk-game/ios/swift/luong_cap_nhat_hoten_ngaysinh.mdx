This document describes the SDK's flow for updating full name and date of birth, built from the actual code.
The project has **two related screens**:

- **`InformationView`** – updates **full name + date of birth** together (along with identity
  information: ID card/passport number, issue date, issue place, address) via the `PATH_PROFILE_PASSPORT` endpoint.
  This is the screen for completing account/identity information (`requireSecurityLevel`).
- **`UpdateBirthday`** – updates **only the date of birth** via the `PATH_UPDATE_INFO_V2` endpoint.
  Opened from the personal information screen `PersonalView` (there is no separate field for editing full name
  here; the full name is only displayed as a title).

Both attach a Bearer accessToken and automatically refresh the token when `code = 86` occurs.

## Option 1 – `InformationView` (full name + date of birth together)

```mermaid
%% width: 1100
flowchart TD
    A["Open InformationView<br/>Enter full name, date of birth + identity information"] --> B["pressSave()"]

    B --> C{Check each field in order}
    C -- Full name empty --> C1([Error at Full name field])
    C -- Date of birth empty --> C2([Error at Date of birth field])
    C -- Date of birth wrong format dd/MM/yyyy --> C3([Error at Date of birth field])
    C -- ID card/passport empty/invalid --> C4([Error at Identity field])
    C -- Issue date empty --> C5([Error at Issue date field])
    C -- Issue place empty --> C6([Error at Issue place field])
    C -- Address empty --> C7([Error at Address field])
    C -- Valid --> D["updateInfoUser()<br/>Convert date to yyyy-MM-dd"]

    D --> E["POST PATH_PROFILE_PASSPORT<br/>fullName, birthday, passport,<br/>passportDate, passportPlateOfIssue, address"]
    E --> F{Result}
    F -- Network error --> F1([Toast: Update failed])
    F -- code != 0 --> F2([Toast: Update failed])
    F -- code = 0 --> G["Toast: Update successful<br/>loginSuccess + registerTimerTask<br/>showOrHideFloatingButton"]
    G --> H([Close screen])
```

### Description – Option 1

The user enters full name (`tfName`), date of birth (`tfBirthDay`, selected via UIDatePicker), and the
identity fields. When the save button is pressed, `pressSave()` checks in order:

- Full name must not be empty.
- Date of birth must not be empty and must match the format `dd/MM/yyyy`.
- ID card/passport number must not be empty and must be valid (`^[0-9]{9,12}$` or passport format `^[A-Z][0-9]{8}$`).
- Issue date, issue place, and address must not be empty.

If valid → `updateInfoUser()` converts the date of birth (and issue date) to `yyyy-MM-dd` then calls
`PATH_PROFILE_PASSPORT` (POST) with `fullName`, `birthday`, `passport`, `passportDate`,
`passportPlateOfIssue`, `address` (along with `deviceId`, `os`, `osVersion`, `ip`).

- `code = 0`: shows the toast "Account information updated successfully", calls `loginSuccess()` (fires the
  `loginSuccess` delegate + `registerTimerTask`), `showOrHideFloatingButton()`, then closes the screen.
- Network error or `code != 0`: shows the toast "Failed to update account information!".

> Note: this screen updates **full name and date of birth together** in a single request, but requires
> all identity information to be filled in before it can be saved.

## Option 2 – `UpdateBirthday` (date of birth only, opened from `PersonalView`)

```mermaid
%% width: 1100
flowchart TD
    A["PersonalView<br/>List: Email, Phone, Identity, Date of birth"] --> B{Select row}
    B -- Date of birth id=4 --> C["Open UpdateBirthday<br/>pass userBirthDay"]
    B -- Email id=1 not verified --> B1([Open VerifyEmail])
    B -- Phone id=2 not verified --> B2([Open VerifyPhone])
    B -- Identity id=3 --> B3([Open UpdateID])

    C --> D[Select date of birth via UIDatePicker<br/>limited 1950 - 2014] --> E["btnUpdateClick()"]
    E --> F{Check date of birth}
    F -- Empty --> F1([Error: enter date of birth])
    F -- Wrong format dd/MM/yyyy --> F2([Error: incorrect format])
    F -- Valid --> G["doUpdateBirthday()<br/>Convert to yyyy-MM-dd"]

    G --> H["POST PATH_UPDATE_INFO_V2<br/>birthday, type = 1"]
    H --> I{Error code}
    I -- code 86 --> I1["doRefreshWithAction → press update again"]
    I1 --> H
    I -- code != 0 --> I2([handleErrorCode → show error])
    I -- code = 0 --> J([Alert: Update successful<br/>callback CallbackSuccess → close<br/>PersonalView refreshDisplay])
```

### Description – Option 2

`PersonalView` is a list-style personal information screen (Email, Phone number, Identity,
Date of birth, Sign out). The account's full name is only displayed in the title, and is not editable here. Selecting the
**Date of birth** row (`id = 4`, type `.edit`) opens `UpdateBirthday` (passing the current date of birth).

In `UpdateBirthday`, the user selects a date via `UIDatePicker` (limited from 01/01/1950 to
01/01/2014). `btnUpdateClick()` checks that the date of birth is not empty and matches the format `dd/MM/yyyy`,
then `doUpdateBirthday()` converts it to `yyyy-MM-dd` and calls `PATH_UPDATE_INFO_V2` (POST) with
`birthday`, `type = 1`.

- `code = 0`: shows the "Update successful" alert, fires `callback(CallbackSuccess)` → closes the screen;
  `PersonalView` receives the callback and calls `refreshDisplay()` to refresh the list.
- `code = 86` (token expired): `doRefreshWithAction` refreshes the token then automatically presses update again.
- other errors: `handleErrorCode`.

## Endpoints used

- `PATH_PROFILE_PASSPORT` – updates full name + date of birth + identity information (POST) – used in `InformationView`
- `PATH_UPDATE_INFO_V2` – updates date of birth (POST, `birthday`, `type = 1`) – used in `UpdateBirthday`

## Notes

- Date of birth is always entered/displayed as `dd/MM/yyyy` in the UI, but sent to the server as `yyyy-MM-dd`.
- `InformationView` is a combined update screen (requiring full identity information) tied to the security
  completion flow (`requireSecurityLevel`); on success it continues the login via `loginSuccess()`.
- `UpdateBirthday` only changes the date of birth, automatically refreshes the token on `code = 86`, and returns the
  result to `PersonalView` via callback to refresh the display.
- The current SDK **has no dedicated screen for editing "full name" alone**; the full name can only be
  updated as part of `InformationView`.
