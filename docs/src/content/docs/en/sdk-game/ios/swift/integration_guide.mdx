## 1. Required files

Before integrating, you need to prepare all of the following files (provided by the VTVLive team):

1. `AFNetworking.xcframework`
2. `iTapSdk.xcframework`
3. `ISdkTrackier.xcframework`
4. Google-Facebook `.plist`
5. `AppConfigDefault.plist`
6. Google-Facebook `.plist.txt`
7. Sample demo project (example)
8. `.mobileprovision` file

:::caution
If you did not receive all of the files above, or have any questions during integration, please contact the VTVLive team for support.
:::

After testing is complete in the dev environment, we will provide you with a dedicated key for the production environment.

## 2. SDK integration steps

To integrate the SDK, follow the steps below in the exact order given.

### 2.1. Add frameworks and libraries to the project

- In the **main project** (app target), select **Embed & Sign** for the libraries listed above.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image1.png)

- In **UnityFramework** (if the game is built from Unity), select **Do Not Embed** for the libraries — since these libraries are already embedded in the main target, this avoids duplication.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image2.png)

### 2.2. Add the Notification Service Extension

This extension helps the SDK correctly process and display push notification content (including notifications with images or custom data from Firebase).

1. Open the iOS project in **Xcode**.
2. Go to **File > New > Target...**

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image3.png)

3. In the template list, find and select **Notification Service Extension**.
4. Click **Next**, name the target — for example `FirebaseNotificationServiceExtension` — then click **Finish**.
5. When Xcode asks whether to activate the new scheme, choose **Activate**.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image4.png)

### 2.3. Add package dependencies

Add the necessary packages (e.g. Firebase) to the project via **Swift Package Manager**:

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image5.png)

### 2.4. Configure FirebaseNotificationServiceExtension

Open the extension's `NotificationService.swift` file and edit the content as follows:

```swift
import UserNotifications
import Firebase
import FirebaseMessaging

class NotificationService: UNNotificationServiceExtension {

    var contentHandler: ((UNNotificationContent) -> Void)?
    var bestAttemptContent: UNMutableNotificationContent?

    override func didReceive(_ request: UNNotificationRequest, withContentHandler contentHandler: @escaping (UNNotificationContent) -> Void) {
        self.contentHandler = contentHandler
        bestAttemptContent = (request.content.mutableCopy() as? UNMutableNotificationContent)

        if let bestAttemptContent = bestAttemptContent {
            FIRMessaging.extensionHelper().populateNotificationContent(bestAttemptContent, withContentHandler: contentHandler)
        }
    }

    override func serviceExtensionTimeWillExpire() {
        if let contentHandler = contentHandler, let bestAttemptContent = bestAttemptContent {
            contentHandler(bestAttemptContent)
        }
    }
}
```

After this step, the project structure in Xcode will look like the image below:

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image6.png)

In addition:

- To enable Sign in with Apple, you need to enable the **Sign in with Apple** capability for the main target.
- To receive push notifications, you need to add the **Push Notifications** capability, and also enable **Background Fetch** and **Remote Notifications** under **Background Modes**.

## 3. Integrating the SDK functions

The SDK provides a single `Sdk.sharedInstance` singleton for all main features, and a separate `SdkTracking.shared` singleton for event tracking functions. This section explains the correct usage lifecycle order: initialize → login → in-game actions → logout.

### 3.1. Initialize the SDK

In `AppDelegate.swift`, import the SDK, declare `AppDelegate` conforming to the `SdkDelegate` protocol, and initialize the SDK as soon as the app launches:

```swift
import UIKit
import iTapSdk

@main
class AppDelegate: UIResponder, UIApplicationDelegate, SdkDelegate {

    func application(_ application: UIApplication, didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?) -> Bool {
        Sdk.sharedInstance.initWithDelegate(self, application: application, launchOptions: launchOptions, environment: .prod)
        Sdk.sharedInstance.setLocationFloatingButton(width: 20, height: 100)
        return true
    }

    // Required: forward the URL callback for Facebook / Google Sign-In
    func application(_ application: UIApplication, open url: URL, options: [UIApplication.OpenURLOptionsKey: Any] = [:]) -> Bool {
        return Sdk.sharedInstance.application(application, open: url, options: options)
    }
}
```

- While integrating and testing, change `environment` to `.dev`:

```swift
Sdk.sharedInstance.initWithDelegate(self, application: application, launchOptions: launchOptions, environment: .dev)
```

Set up the `SdkDelegate` callbacks (all are optional — only implement the ones you need) in an extension of `AppDelegate`:

```swift
extension AppDelegate {

    func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
        // Login succeeded — user.accountID, user.accountName
    }

    func sdk(_ sdk: Sdk, logout user: User) {
        // Logout succeeded
    }

    func sdk(_ sdk: Sdk, didPurchaseSuccess transactionInfo: TransactionInfo) {
        // Payment succeeded — transactionInfo.productId, transactionInfo.transId...
    }

    func sdk(_ sdk: Sdk, didPurchaseFailed transactionInfo: TransactionInfo, purchaseError: String?) {
        // Payment failed
    }

    func sdk(_ sdk: Sdk, getLanguage language: String) {
        // SDK language has just changed
    }

    func sdkCloseLoginView() {
        // Login screen has just been closed
    }
}
```

:::note
The Swift version of the SDK automatically handles requesting permissions (notification, App Tracking Transparency) during initialization — there is no manual permission-popup toggle function like the old Objective-C version.
:::

### 3.2. Login

Always call `login()` **before the game starts**. The SDK will automatically show the login dialog if this is the user's first time entering the game, or automatically refresh the token if the user has logged in before.

```swift
Sdk.sharedInstance.login()
```

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image8.png)

If everything succeeds, the login dialog will display as shown above.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image9.png)

When the user logs in successfully, the user information is returned via the `sdk(_:loginSuccess:accessToken:refreshToken:)` callback of the `SdkDelegate` you registered with the SDK.

### 3.3. Logout

```swift
Sdk.sharedInstance.logout()
```

When logout succeeds, the SDK will call back `sdk(_:logout:)` to notify the game. There's also `Sdk.sharedInstance.forceLogout()` — logs out immediately without calling the server API to revoke the refresh token (used when the login session has already expired on the server side).

### 3.4. List products

Get the list of products (top-up packages) from the App Store. You should call this function right after a successful login, since you'll need the product price to send to the tracking system when the user makes a payment.

```swift
func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
    Sdk.sharedInstance.listProducts { error, products in
        // products: [IAPProduct]?
    }
    Sdk.sharedInstance.showOrHideFloatingButton()
}
```

:::note
You should place the `listProducts` call inside the `loginSuccess` callback, as in the example above — no need to wait for anything else.
:::

### 3.5. Set Language

Call the following function to change the SDK's display language:

```swift
Sdk.sharedInstance.setLanguage(input: "vi")
```

Supported language codes:

| Code | Language |
| --- | --- |
| `vi` | Vietnamese |
| `en` | English |
| `th` | Thai |
| `zh` | Chinese |

The SDK also calls back `sdk(_:getLanguage:)` on the `SdkDelegate` whenever the language is changed (including on the first initialization).

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image10.png)

### 3.6. Show countdown

To display the countdown UI as shown below, call `showCountdown()` **after login is complete**:

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image11.png)

```swift
func sdk(_ sdk: Sdk, loginSuccess user: User, accessToken: String, refreshToken: String) {
    Sdk.sharedInstance.listProducts { error, products in }
    Sdk.sharedInstance.showOrHideFloatingButton()
    Sdk.sharedInstance.showCountdown()
}
```

You can check in advance whether the countdown event is available with `Sdk.sharedInstance.isCountdownAvailable() -> Bool`.

### 3.7. Receive Gift

```swift
Sdk.sharedInstance.showReceiveGift()
```

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image13.png)

:::note
This function takes no parameters — the SDK automatically uses the `characterId`/`serverId` stored from the most recent call to `mappingUser(...)` ([section 3.10](#310-ánh-xạ-thông-tin-nhân-vật-map-user)). So you need to call `mappingUser` before showing the receive gift button.
:::

### 3.8. Make payment

```swift
Sdk.sharedInstance.payProduct(itemProduct.productId ?? "", forCharacterId: "17782088632480", onServerId: "s6003")
```

- First parameter (`productID`): obtained from the `productId` of an `IAPProduct` in the `listProducts` result from [section 3.4](#34-lấy-danh-sách-sản-phẩm-list-products).
- `forCharacterId`: the character's Id in the game.
- `onServerId`: the server's Id.

The payment result (success or failure) will be returned via the `sdk(_:didPurchaseSuccess:)` or `sdk(_:didPurchaseFailed:purchaseError:)` callback of `SdkDelegate`, respectively.

### 3.9. Show/hide the floating button (Show dashboard)

```swift
Sdk.sharedInstance.showOrHideFloatingButton()
```

### 3.10. Map User

Call this function to send the user's current character information to the SDK, used for tracking and other features related to the character/server (including `showReceiveGift()` in [section 3.7](#37-nhận-quà-receive-gift)):

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image12.png)

```swift
Sdk.sharedInstance.mappingUser(
    "name",
    characterId: "1",
    characterLevel: "1",
    serverName: "test",
    serverId: "1"
)
```

- First parameter (unlabeled): the character's name.
- `characterId`: the character's Id.
- `characterLevel`: the character's current level.
- `serverName`: server name.
- `serverId`: server Id.

The SDK also has `Sdk.sharedInstance.levelUpUser(_:characterId:characterLevel:serverName:serverId:vip:)` — call this whenever the character levels up or reaches a new VIP tier, so the tracking system can record the milestone.

## 4. Log Function (SdkTracking)

The functions below live on the **`SdkTracking.shared`** singleton (different from `Sdk.sharedInstance`), and are used to send tracking events to the system, helping to measure user behavior across the entire game-playing lifecycle — from opening the app, downloading patches, creating a character, to entering the game.

Color legend in the original Flowchart diagram:

- **Gray**: processing steps on the Game side.
- **Yellow**: points where the Game needs to call SDK functions.

See the "Login or Start Game" section in the [Flowchart](#6-sơ-đồ-luồng-flowchart) for the exact position where the log functions below should be placed in the game's flow.

```swift
SdkTracking.shared.logStartGameScreen()
SdkTracking.shared.logEnterGamePlay()
SdkTracking.shared.logStartTutorial()
SdkTracking.shared.logCompleteTutorial()
```

#### `logEnterGamePlay()`

Tracks the event of the user entering the gameplay screen, right after tapping the "Enter Game" button.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image14.png)

#### `logPatchStart` — Start downloading resources (patch)

```swift
SdkTracking.shared.logPatchStart(sizeMB: 500, withVerrsion: "1.0.1", withNetworkType: "wifi")
```

| Parameter | Meaning |
| --- | --- |
| `sizeMB` | The patch file size to download, in MB |
| `withVerrsion` | Installation package version |
| `withNetworkType` | Network type (`"wifi"`, `"4g"`...) |

#### `logPatchSuccess` — Resource download completed

```swift
SdkTracking.shared.logPatchSuccess(durationSec: 450, withAvgSpeedKbps: 111, withCdnNode: "192.168.0.2")
```

| Parameter | Meaning |
| --- | --- |
| `durationSec` | Time from start of download to completion (seconds) |
| `withAvgSpeedKbps` | Average download speed (Kbps) |
| `withCdnNode` | CDN node used for the download |

#### `logPatchError` — Resource download failed

```swift
SdkTracking.shared.logPatchError(errorCode: "500", withRetryCount: 1, withFailedUrl: "https://cdn.game.com/patch/v120.zip", withCdnNode: "192.168.0.2")
```

| Parameter | Meaning |
| --- | --- |
| `errorCode` | Error code |
| `withRetryCount` | Number of retries due to error |
| `withFailedUrl` | URL that failed during download |
| `withCdnNode` | CDN node where the error occurred |

#### `logExtractStarted` — Start extracting resources

```swift
SdkTracking.shared.logExtractStarted(totalSizeMb: "500", withTotalSize: "400")
```

| Parameter | Meaning |
| --- | --- |
| `totalSizeMb` | Size after extraction, in MB |
| `withTotalSize` | Number of files in the patch to extract |

#### `logExtractFinished` — Resource extraction completed

```swift
SdkTracking.shared.logExtractFinished(durationSec: 100, withResultCode: "ok")
```

| Parameter | Meaning |
| --- | --- |
| `durationSec` | Time from start of extraction to completion (seconds) |
| `withResultCode` | Result code — `"ok"`/`0`: OK, `1`: Disk Full |

#### `logCharCreateStart` — Start character creation

```swift
SdkTracking.shared.logCharCreateStart(serverId: "100")
```

:::note
You should set up an internal timer to measure the time from the start of character creation to completion — this value needs to be passed to `logCharCreateSuccess` below.
:::

#### `logCharCreateSuccess` — Character creation succeeded

```swift
SdkTracking.shared.logCharCreateSuccess(
    serverId: "100",
    withCharId: "1001",
    withCharName: "test",
    withCharClass: "1",
    withDurationSec: 5
)
```

| Parameter | Meaning |
| --- | --- |
| `serverId` | Server id |
| `withCharId` | Character id |
| `withCharName` | Character name |
| `withCharClass` | Character class id (class_id) |
| `withDurationSec` | Time from start of creation to success (seconds) |

#### `logCharCreateError` — Character creation failed

```swift
SdkTracking.shared.logCharCreateError(errorCode: "NAME_DUPLICATED", withCharName: "test", withServerId: "1")
```

#### `logCharSelect` — Select character

Call this function right after the user selects a server and a character to enter the game.

```swift
SdkTracking.shared.logCharSelect("1", withCharacterName: "name", withCharLevel: "1")
```

## 5. Sync information updates per Decree 147

Unlike the old Objective-C version (2 manually-called functions, `isNeedShowEventProfileSync` + `showEventProfile`), the Swift version combines these into a **single function** `checkShow147`, and the SDK **automatically displays the screen** if needed — you just need to call it and (optionally) read the result via the completion handler:

```swift
Sdk.sharedInstance.checkShow147 { needVerify in
    // needVerify == true: the SDK has automatically opened the information sync screen (Event Profile)
    // needVerify == false: nothing else to do, the user can proceed into the game
}
```

Should be called right inside the `loginSuccess` callback, before letting the user into the game's main screen.

## 7. Main classes/types in the SDK

**`IAPProduct`** — information about a product (top-up package):

| Property | Description |
| --- | --- |
| `productId` | Product Id, matching the product id declared on the App Store |
| `productDescription` | Product description |
| `localizedPrice` | Product price displayed according to the device's locale |
| `price` / `currencyCode` / `priceLocale` | Raw price, currency code, locale (use when you need to format the price yourself) |
| `appAmount` | Amount of gold the user receives when purchasing this package |
| `amount` | Corresponding vXu amount |

**`User`** — user information:

| Property | Description |
| --- | --- |
| `accountID` | User account Id |
| `accountName` | Account username |

**`TransactionInfo`** — payment transaction information (returned via `didPurchaseSuccess`/`didPurchaseFailed`):

| Property | Description |
| --- | --- |
| `transId` | Transaction Id |
| `productId` | Id of the purchased product |
| `purchasedToken` | Transaction confirmation token from the App Store |
| `paymentOrderId` | Order Id on the payment system side |
| `confirmByServer` | Confirmation status from the server |

**`Sdk`** — the SDK's main singleton:

| Member | Description |
| --- | --- |
| `Sdk.sharedInstance` | The SDK's singleton |
| `delegate: SdkDelegate?` | Where callbacks are received (login, logout, payment...) |
| `environment: Environment` | `.prod` or `.dev` |
| `getCurrentAccessToken() -> String` | Gets the current access token after a successful login |

### How to export the IPA file to upload to the App Store

:::danger[Needs verification]
The original document only has screenshots for these steps, with no accompanying text description. The content of the 7 steps below was interpreted by the documentation team based on Xcode's standard archive/export process — please cross-check with the actual screenshots below before following along, and report back if any step doesn't match.
:::

Follow these steps in Xcode:

1. Select **Any iOS Device (arm64)** as the build destination instead of a simulator.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image23.jpg)

2. Go to **Product > Archive** for Xcode to build and package the archive.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image24.jpg)

3. Once archiving is complete, the **Organizer** window will automatically open and display the archive you just created. Select **Distribute App**.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image25.jpg)

4. Choose the appropriate distribution method (for example **App Store Connect** or **Ad Hoc**) and follow Xcode's wizard steps.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image26.jpg)

5. Before exporting, be sure to check that the **aps-environment** entry in the entitlements is `production` (not `development`) — otherwise push notifications will not work in the release build.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image27.png)

6. Once the export is complete, select **Show in Finder** to open the folder containing the `.ipa` file.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image28.png)

7. Right-click the `.ipa` file (or the `.xcarchive` file) and select **Show Package Contents** to get the dSYM file inside if you need to send debug symbols.

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image29.png)

![](BASE_STORAGE/v2.0.0/ios_swift_integration_guide_image30.png)

:::note
When you need debugging support, please send the VTVLive team both the **dSYM** file and the corresponding **.ipa** file.
:::
