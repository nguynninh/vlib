1. `AFNetworking.xcframework`
2. `FBAEMKit.xcframework`
3. `FBSDKCoreKit_Basics.xcframework`
4. `FBSDKCoreKit.xcframework`
5. `FBSDKLoginKit.xcframework`
6. `FBSDKShareKit.xcframework`
7. `iTapSdk.xcframework`

## 2. SDK integration steps

To integrate the SDK, follow the steps below in the exact order given.

### 2.1. Add frameworks and libraries to the project

- In the **main project** (app target), select **Embed & Sign** for the libraries listed above.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image1.png)

- In **UnityFramework** (if the game is built from Unity), select **Do Not Embed** for the libraries — since these libraries are already embedded in the main target, this avoids duplication.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image2.png)

### 2.2. Add the Notification Service Extension

This extension helps the SDK correctly process and display push notification content (including notifications with images or custom data from Firebase).

1. Open the iOS project in **Xcode**.
2. Go to **File > New > Target...**

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image3.png)

3. In the template list, find and select **Notification Service Extension**.
4. Click **Next**, name the target — for example `FirebaseNotificationServiceExtension` — then click **Finish**.
5. When Xcode asks whether to activate the new scheme, choose **Activate**.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image4.png)

### 2.3. Install the Firebase SDK for the Extension

1. Open the `Podfile` and **add a new target** dedicated to the extension you just created:

```Swift

  use_frameworks!
  pod 'GoogleSignIn', '7.1.0'

  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'AppsFlyerFramework', '6.17.7'
  pod 'JWT', '2.2.0'
  pod 'TikTokBusinessSDK', '1.5.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'FirebaseCrashlytics', '12.0.0'
end
target 'UnityFramework' do
  use_frameworks!
  pod 'GoogleSignIn', '7.1.0'
  pod 'Firebase', '12.0.0'
  pod 'FirebaseMessaging', '12.0.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'AppsFlyerFramework', '6.17.2'
  pod 'JWT', '2.2.0'
  pod 'TikTokBusinessSDK', '1.5.0'
  pod 'FirebaseRemoteConfig', '12.0.0'
  pod 'FirebaseCrashlytics', '12.0.0'
end

target 'FirebaseNotificationServiceExtension' do
  use_frameworks!
 pod 'Firebase', '12.0.0'
 pod 'FirebaseMessaging', '12.0.0'
end

post_install do |lib|
    lib.pods_project.targets.each do |target|
        if target.name == 'GoogleSignIn' || target.name == 'Firebase' || target.name == 'FirebaseRemoteConfig' || target.name == 'FirebaseMessaging' || target.name == 'AppsFlyerFramework' ||  target.name == 'JWT' ||  target.name == 'TikTokBusinessSDK'
```

2. Run the following commands to cleanly reinstall dependencies:

```bash
pod cache clean --all
pod deintegrate
pod install
```

### 2.4. Configure FirebaseNotificationServiceExtension

1. Open the `.xcworkspace` file (not the `.xcodeproj`).
2. Edit the extension's `NotificationService.m` file as follows:

```Objective-C
#import "NotificationService.h"
@import Firebase;
@import FirebaseMessaging;
@interface NotificationService ()
@property (nonatomic, strong) void (^contentHandler)(UNNotificationContent *contentToDeliver);
@property (nonatomic, strong) UNMutableNotificationContent *bestAttemptContent;
@end
@implementation NotificationService
- (void)didReceiveNotificationRequest:(UNNotificationRequest *)request withContentHandler:(void (^)(UNNotificationContent * _Nonnull))contentHandler {
    self.contentHandler = contentHandler;
    self.bestAttemptContent = [request.content mutableCopy];
    self.bestAttemptContent.title = [NSString stringWithFormat:@"%@", self.bestAttemptContent.title];
    [[FIRMessaging extensionHelper] populateNotificationContent:self.bestAttemptContent
                                                withContentHandler:contentHandler];
}
- (void)serviceExtensionTimeWillExpire {
    [[FIRMessaging extensionHelper] populateNotificationContent:self.bestAttemptContent
                                                withContentHandler:self.contentHandler];
}
@end
```

- To enable Sign in with Apple, you need to enable the **Sign in with Apple** capability for the main target.
- To receive push notifications, you need to add the **Push Notifications** capability, and also enable **Background Fetch** and **Remote Notifications** under **Background Modes**.

## 3. Integrating the SDK functions

This section explains how to call the SDK's main functions in code, following the correct usage lifecycle order: initialize → login → in-game actions → logout.

### 3.1. Initialize the SDK

In the `AppDelegate.h` file, import the SDK and declare `AppDelegate` conforming to the `SdkDelegate` protocol:

```Objective-C
#import <UIKit/UIKit.h>
#import <iTapSdk/iTapSdk.h>
@interface AppDelegate : UIResponder <UIApplicationDelegate,SdkDelegate>

@property (strong, nonatomic) UIWindow *window;
@end
```

In the `AppDelegate.m` file, initialize the SDK as soon as the app launches:

```Objective-C
- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    [[Sdk sharedInstance] initWithDelegate:self application:application launchOptions:launchOptions isProdEnv:TRUE];
    [[Sdk sharedInstance] setLocationFloatingButton:20 with:100];
    [[Sdk sharedInstance] setGrantEnv:YES];
    return YES;
}
```

- While integrating and testing, change `isProdEnv` to `FALSE` to run in the dev environment:

```Objective-C
[[Sdk sharedInstance] initWithDelegate:self application:application launchOptions:launchOptions isProdEnv:FALSE];
```

- `setGrantEnv:YES` — displays the permission request popup (ads, tracking...) when entering the game. Set `setGrantEnv:NO` if you don't want this popup shown.

### 3.2. Login

Always call the `login` function **before the game starts**. The SDK will automatically show the login dialog if this is the user's first time entering the game, or automatically refresh the token if the user has logged in before. See the [Flowchart section](#6-sơ-đồ-luồng-flowchart) below for more details on the login flow.

```Objective-C
[[Sdk sharedInstance] login];
```

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image7.png)

If everything succeeds, the login dialog will display as shown above.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image8.png)

When the user logs in successfully, the user information is returned via the `loginSuccess` function of the `SdkDelegate` you registered with the SDK.

### 3.3. Logout

```Objective-C
[[Sdk sharedInstance] logout];
```

When logout succeeds, the SDK will call back the `logout` function of `SdkDelegate` to notify the game.

### 3.4. List products

Get the list of products (top-up packages) from the store (App Store). You should call this function right after a successful login, since you'll need the product price to send to the tracking system when the user makes a payment.

```Objective-C
-(void)loginSuccess:(User *)user withAccessToken:(NSString *)accessToken andRefreshToken:(NSString *)refreshToken{
    
    [[Sdk sharedInstance] listProducts:^(NSError *error, NSArray<IAPProduct*> * _Nullable result) {
        
    }];
    [[Sdk sharedInstance] showOrHideFloatingButton];
    
}
```

:::note
You should place the `listProducts` call in code that only runs **after a successful login**, as in the example above.
:::

### 3.5. Set Language

Call the following function to change the SDK's display language, with the corresponding parameter:

```Objective-C
[[Sdk sharedInstance] setLanguage:@"vi"];
```

Supported language codes:

| Code | Language |
| --- | --- |
| `vi` | Vietnamese |
| `en` | English |
| `th` | Thai |
| `zh` | Chinese |

The SDK also provides the `getLangaugeSdk` delegate to notify the game whenever the language is changed.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image9.png)

### 3.6. Show countdown

To display the countdown UI as shown below, call `showCountdown` **after login is complete**, inside the `loginSuccess` callback of `AppDelegate`:

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image10.png)

```Objective-C
-(void)loginSuccess:(User *)user withAccessToken:(NSString *)accessToken andRefreshToken:(NSString *)refreshToken{

    [[Sdk sharedInstance] listProducts:^(NSError *error, NSArray<IAPProduct*> * _Nullable result) {

    }];
    [[Sdk sharedInstance] showOrHideFloatingButton];
    [[Sdk sharedInstance] showCountdown];

}
```

### 3.7. Receive Gift

When the user taps the gift box button, call the following function:

```Objective-C
[[Sdk sharedInstance] showReceiveGift:@"1111111" withCharacterId:@"11112"];
```

- `serverId`: the server's Id.
- `characterId`: the character's Id.

### 3.8. Make payment

```Objective-C
[[Sdk sharedInstance] payProduct:itemProduct.productId forCharacterId:@"17782088632480" onServerId:@"s6003"];
```

- `itemProduct.productId`: obtained from the result of `listProducts` in [section 3.4](#34-lấy-danh-sách-sản-phẩm-list-products).
- `forCharacterId`: the character's Id in the game.
- `onServerId`: the server's Id.

The payment result (success or failure) will be returned via the `didPurchaseSuccess` or `didPurchaseFailed` function of the `SdkDelegate` you registered with the SDK.

### 3.9. Show/hide the floating button (Show dashboard)

```Objective-C
[[Sdk sharedInstance] showOrHideFloatingButton];
```

### 3.10. Map User

Call this function to send the user's current character information to the SDK, used for tracking and other features related to the character/server:

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image11.png)

```Objective-C
-(void) mappingUser:(NSString*)characterName
        characterId:(NSString*)characterId
     characterLevel:(NSString*)characterLevel
        serverName:(NSString*)serverName
          serverId:(NSString*)serverId;

// Example:
[[SdkTracking sharedInstance] mappingUser: @"name" characterId : @1 characterLevel : @1 serverName : @"test" serverId : @"1"];
```

- `characterName`: character name.
- `characterId`: character Id.
- `characterLevel`: the character's current level.
- `serverName`: server name.
- `serverId`: server Id.

## 4. Receive Gift (no parameters)

When the user taps the gift box button, call:

```Objective-C
[[Sdk sharedInstance] showReceiveGift];
```

## 5. Log Function

The functions below are used to send tracking events to the system, helping to measure user behavior across the entire game-playing lifecycle — from opening the app, downloading patches, creating a character, to entering the game.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image13.png)

Color legend in the diagram above:

- **Gray**: processing steps on the Game side.
- **Yellow**: points where the Game needs to call SDK functions.

See the "Login or Start Game" section in the [Flowchart](#6-sơ-đồ-luồng-flowchart) for the exact position where the log functions below should be placed in the game's flow.

```Objective-C
-(void) logStartGameScreen;
-(void) logEnterGamePlay;
-(void) logStartTutorial;
-(void) logCompleteTutorial;
```

#### `logEnterGamePlay`

Tracks the event of the user entering the gameplay screen, right after tapping the "Enter Game" button.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image14.png)

#### `logPatchStart` — Start downloading resources (patch)

```Objective-C
-(void) logPatchStart: (NSNumber * _Nullable) sizeMB withVerrsion:(NSString * _Nullable)version withNetworkType: (NSString * _Nullable) networkType;

// sizeMB  : the patch file size that needs downloading, in MB
// version : installation package version

// Example:
[[SdkTracking sharedInstance] logPatchStart: @"500" withVerrsion : @"1.0.1" withNetworkType : @"wifi"];
```

#### `logPatchSuccess` — Resource download completed

```Objective-C
-(void) logPatchSuccess: (NSNumber * _Nullable) durationSec withAvgSpeedKbps: (NSNumber * _Nullable) avgSpeedKbps withCdnNode :(NSString * _Nullable) cdnNode;

// durationSec  : time from start of download to completion (seconds)
// avgSpeedKbps : average download speed (Kbps)
// cdnNode      : CDN node used for the download

// Example:
[[SdkTracking sharedInstance] logPatchSuccess: @"500" withAvgSpeedKbps : @"111" avgSpeedKbps : @"450" withCdnNode: @"192.168.0.2"];
```

#### `logPatchError` — Resource download failed

Call this when the resource download is interrupted or fails.

```Objective-C
-(void) logPatchError:(NSString * _Nullable) errorCode withRetryCount:(NSNumber * _Nullable) retryCount withFailedUrl:(NSString * _Nullable) failedUrl withCdnNode :(NSString * _Nullable) cdnNode;

// errorCode   : error code
// retryCount  : number of retries due to error
// failedUrl   : URL that failed during download
// cdnNode     : CDN node where the error occurred

// Example:
[[SdkTracking sharedInstance] logPatchError: @"500" withRetryCount: @1 withFailedUrl: @"https://cdn.game.com/patch/v120.zip" withCdnNode : @"192.168.0.2"];
```

#### `logExtractStarted` — Start extracting resources

Call this right after the download finishes, when extraction/installation begins.

```Objective-C
-(void) logExtractStarted:(NSString * _Nullable) totalSizeMb withTotalSize: (NSString * _Nullable) totalSize;

// totalSizeMb : size after extraction, in MB
// totalSize   : number of files in the patch to extract (omit if unavailable)

// Example:
[[SdkTracking sharedInstance] logExtractStarted: @"500" withTotalSize : @"400"];
```

#### `logExtractFinished` — Resource extraction completed

Call this when extraction is finished and the app is ready to show the login screen.

```Objective-C
-(void) logExtractFinished:(NSNumber * _Nullable) durationSec withResultCode:(NSString * _Nullable) resultCode;

// durationSec : time from start of extraction to completion (seconds)
// resultCode  : result code — 0: OK, 1: Disk Full

// Example:
[[SdkTracking sharedInstance] logExtractFinished: @100 withResultCode : @"ok"];
```

#### `logCharCreateStart` — Start character creation

```Objective-C
-(void) logCharCreateStart: (NSString * _Nullable) serverId;

// serverId : server id

// Example:
[[SdkTracking sharedInstance] logCharCreateStart: @"100"];
```

:::note
You should set up an internal timer to measure the time from the start of character creation to completion — this value needs to be passed to `logCharCreateSuccess` below.
:::

#### `logCharCreateSuccess` — Character creation succeeded

```Objective-C
-(void) logCharCreateSuccess: (NSString * _Nullable) serverId withCharId:(NSString * _Nullable) charId withCharName:(NSString * _Nullable) charName withCharClass:(NSString * _Nullable) charClass withDurationSec: (NSNumber * _Nullable) durationSec;

// serverId    : server id
// charId      : character id
// charName    : character name
// charClass   : character class id (class_id)
// durationSec : time from start of creation to success (seconds)

// Example:
[[SdkTracking sharedInstance] logCharCreateSuccess: @"500" withVerrsion : @"1.0.1" withNetworkType : @"wifi"];
```

:::danger[Example may be incorrect]
The example line above is kept unchanged from the original document, but the `withVerrsion`/`withNetworkType` parameters do not match the `logCharCreateSuccess` function signature declared above (it appears to have been mistakenly copied from the `logPatchStart` example). Please confirm the correct parameters with the SDK development team before using.
:::

#### `logCharCreateError` — Character creation failed

```Objective-C
-(void) logCharCreateError:(NSString * _Nullable) errorCode withCharName:(NSString * _Nullable) charName withServerId:(NSString * _Nullable) serverId;

// errorCode : error code
// charName  : character name
// serverId  : server id

// Example:
[[SdkTracking sharedInstance] logCharCreateError: @"NAME_DUPLICATED" withCharName : @"test" withServerId :@"1"];
```

#### `logCharSelect` — Select character

Call this function right after the user selects a server and a character to enter the game.

```Objective-C
-(void) logCharSelect: (NSString * _Nullable) charId withCharacterName :(NSString* _Nonnull) characterName withCharLevel:(NSString * _Nullable) charLevel;

// charId        : character id
// characterName : character name
// charLevel     : character level

// Example:
[[SdkTracking sharedInstance] logCharSelect: @"1" withCharacterName : @"name " withCharLevel : @"1"];
```

## 6. Sync information updates per Decree 147

```Objective-C
dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
    BOOL needShow = [[Sdk sharedInstance] isNeedShowEventProfileSync];
    if (needShow) {
        dispatch_async(dispatch_get_main_queue(), ^{
            [[Sdk sharedInstance] showEventProfile];   // showEventProfile must run on the main thread because it involves UI
        });
    }
});
```

- If `isNeedShowEventProfile()` returns `true`: open the information sync screen (Event Profile) for the user to update.
- If `isNeedShowEventProfile()` returns `false`: allow the user to enter the game directly, no need to show this screen.

### How to export the IPA file to upload to the App Store

:::danger[Needs verification]
The original document only has screenshots for these steps, with no accompanying text description. The content of the 7 steps below was interpreted by the documentation team based on Xcode's standard archive/export process — please cross-check with the actual screenshots below before following along, and report back if any step doesn't match.
:::

Follow these steps in Xcode:

1. Select **Any iOS Device (arm64)** as the build destination instead of a simulator.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image23.png)

2. Go to **Product > Archive** for Xcode to build and package the archive.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image24.png)

3. Once archiving is complete, the **Organizer** window will automatically open and display the archive you just created. Select **Distribute App**.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image25.png)

4. Choose the appropriate distribution method (for example **App Store Connect** or **Ad Hoc**) and follow Xcode's wizard steps.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image26.png)

5. Before exporting, be sure to check that the **aps-environment** entry in the entitlements is `production` (not `development`) — otherwise push notifications will not work in the release build.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image27.png)

6. Once the export is complete, select **Show in Finder** to open the folder containing the `.ipa` file.

![](BASE_STORAGE/v2.0.0/ios_objective_c_integration_guide_image28.png)
