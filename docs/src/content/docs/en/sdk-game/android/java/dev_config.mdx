## Configuration process

1. Configuration on the Hub

    After configuring on the hub successfully and verifying by copying this data into the SDK to check whether the fields are correct, configure it on Firebase Remote Config just like other games.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image4.png)

    1. Global

        Applies to all applications; created automatically and does not need to be edited unless there is an error, in which case report it to BE for a fix. Default value is 0.

    2. App

        Applies to all packages, including iOS, with the parameter taken from appId.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image5.png)

    1. Package

        Applies to a single package, taken from packageId.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image6.png)

    2. List of configuration parameters

2. Configuration on Firebase

    1. Application configuration

        Go to: Setting -> General -> Add app -> Enter the package Id

        After creating the app, **have the department head** update the configuration on Google Cloud to add information to google-service.json.

        Check the json at: https://dandar3.github.io/android/google-services-json-to-xml.html

        It must match the image below.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image8.png)

    2. Server notification configuration

        After correctly configuring google-server.json into the sample app, notifications should be received; you can test beforehand using a Firebase message.

        Project Setting -> Services account

        Make sure to create this only once and keep this file.

        After creating the configuration for both Android and iOS on the Hub, retest notifications using the package configuration on the hub.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image9.png)

        Set it on the hub.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image10.png)

4. Example configuration

    Please refer to another project.

    - Change the package name
    - Change the project name
    - Change the information in string.xml
    - Change google-service.json
    - Change the vtvlive_config_sdk_game_defaults file -> information taken from the hub
    - Change the key used to download the libraries in both the game SDK and game tracking SDK; create an access token key -> developer -> read-api and save it

5. Sample test procedure

    1. Regular login

        Failure -> Recheck the hub configuration and the sample project to verify the package and provided information are correct -> If correct, ask BE whether login has been configured

    2. Registration and Forgot Password

        Failure -> Open the log and see an error that the package name does not exist in reCAPTCHA -> **have the department head** configure it

        Failure -> A dialog shows an error from BE -> The device and network are being spam-flagged by reCAPTCHA; use a different device and 3G network

    3. Google login

        Authentication fails.

        Cause:

        -> The build is unsigned, or the signature on Google Cloud is wrong. Check that the APK, Google Cloud, and store all share the same SHA1 signature

        ! The GG login client ID on the hub might be set incorrectly

    4. Facebook login

        Login error reported.

        In development mode:

        Recheck the Facebook app information.

        Verify you're using the correct test account to log in.

        In public mode:

        Check whether Facebook has granted profile permission -> If not, **have the department head** request the permission from Facebook for the project

    5. Checking events sent to AppsFlyer

        Open the log with the tag appsflyer; if it fires an error that the package name does not exist, **have the department head handle it**

    6. Checking payments

        To be able to test payments, a build must be pushed to internal testing, then the top-up packages must be configured on the store and the hub.

        If payment fails with an unknown error,

        Check that the APK is sending the correct top-up package name.

        If the game side has sent the correct top-up package name but the BE API returns an unknown error,

        **Have the department head** ask the Payment team to enable production and enable the service configuration on Google Cloud.

        Enabling this configuration can take up to 1 day before payments start working.

## Store configuration

1. App registration

    Registration must be done right away since package name registration review can take up to 48 hours.

    After completing the sample project, create a file at the path below.

![](BASE_STORAGE/v2.0.0/android_java_dev_config_image12.png)

    The code is obtained from the store when registering the package name.

    Use the correct keystore, build the APK, and upload it to the store to register the package name.

    Only after the package name is registered can the app be created on the store.
