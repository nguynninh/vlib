代码块是读者在技术文档页面上停留时间最长的地方。一段好的代码不仅要语法正确，还要让读者知道它使用的是哪种语言、属于哪个文件、以及哪些行值得关注。

本页说明如何按照当前文档系统的规范，在 MDX 中编写代码块。

## 基本语法

代码块以三个反引号开头，后面跟语言标识符。文档渲染时，系统会使用该标识符来进行语法高亮。

````mdx showLineNumbers
```ts
const message: string = "你好";
console.log(message);
```
````

结果是代码以 TypeScript 的形式显示。

````typescript title="hello.ts"
const message: string = "你好";
console.log(message);
````

如果省略 `ts`,代码依然会显示,但读者将失去语法高亮,页面也会显得不够清晰。

````
const message: string = "你好";
console.log(message);
````

:::danger
当代码内容需要在里面嵌套展示另一个围栏代码块时(就像本页中的 MDX 示例那样),外层围栏使用的反引号数量必须多于内层——例如内层用三个反引号 ``` 时,外层就要用四个反引号 ````。如果使用相同数量,MDX 会在错误的位置关闭代码围栏,导致页面其余部分被破坏。
:::

## 选择正确的语言

请根据代码的实际内容声明对应的语言。这是一个细节,但会直接影响用户阅读、复制和调试代码的体验。

<Tabs>
    <TabItem label="TypeScript">
        ````mdx showLineNumbers
            ```ts title="src/main.ts"
                const app = createApp();
                app.start();
            ```
        ````
    </TabItem>
    <TabItem label="Java">

        ````mdx showLineNumbers
            ```java title="src/main/java/Main.java"
                public class Main {
                    public static void main(String[] args) {
                        System.out.println("你好");
                    }
                }
            ```
        ````

    </TabItem>
    <TabItem label="JSON">
        ````mdx showLineNumbers
            ```json title="package.json"
                {
                    "scripts": {
                        "dev": "astro dev",
                        "build": "astro build"
                    }
                }
            ```
        ````
    </TabItem>
</Tabs>

建议使用简短且常见的标识符,如 `ts`、`tsx`、`js`、`java`、`kotlin`、`json`、`css`、`scss`、`bash`、`diff`、`mdx` 或 `text`。

:::caution[警告]
有一个不在上述列表中的特殊标识符:`mermaid`。它同样是围栏代码块,但里面的内容描述的是图表,而不是需要语法高亮的代码,因此单独成篇——参见[Mermaid 图表](/zh/internal/web-documentation/ui/code_block_mermaid)。
:::

:::note
如果代码属于某种特定语言,请始终声明其语言标识符。只有内容确实是纯文本时,才使用不带语言标识的代码块。
:::

## 添加文件名

当示例代表某个具体文件时,添加 `title="..."`,让读者知道应该把这段代码放在哪里。

````mdx showLineNumbers
```tsx title="src/components/Button.tsx"
export function Button() {
    return <button>结账</button>;
}
```
````

在安装、配置、迁移指南,或任何需要读者修改特定文件的示例中,`title` 都特别有用。

## 显示行号

行号能让说明更加精确。与其说"下面的配置块",不如说"第 3 行声明了 build 脚本"。

````mdx showLineNumbers
```json title="package.json" showLineNumbers
{
    "scripts": {
        "dev": "astro dev",
        "build": "astro build"
    }
}
```
````

并不需要在每段代码上都开启 `showLineNumbers`。对于一两行的简短示例,行号通常不会带来额外价值。

## 高亮重要行

当示例行数较多、但只有少数几行需要关注时,可以在代码围栏的元信息后用 `{}` 添加行号。这样能让读者第一时间看到重点内容。

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {3}
const app = createApp();

app.use(paymentPlugin);
app.start();
```
````

````ts title="src/main.ts" showLineNumbers {3}
const app = createApp();

app.use(paymentPlugin);
app.start();
````

如果需要强调多个连续的行,可以使用区间:

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {3-4}
const app = createApp();

app.use(paymentPlugin);
app.start();
```
````

````ts title="src/main.ts" showLineNumbers {3-4}
const app = createApp();

app.use(paymentPlugin);
app.start();
````

如果需要强调的行并不相邻,用逗号分隔:

````mdx showLineNumbers
```ts title="src/main.ts" showLineNumbers {1,4}
const app = createApp();
const config = loadConfig();

app.start(config);
```
````

````ts title="src/main.ts" showLineNumbers {1,4}
const app = createApp();
const config = loadConfig();

app.start(config);
````

## 用 diff 描述改动

当文档在讲解如何修改代码时,`diff` 通常比把"修改前"和"修改后"两个代码块并排放置更容易理解。

````mdx showLineNumbers
```diff
- const environment = "development";
+ const environment = import.meta.env.MODE;
```
````

diff 适用于迁移、修复 bug、修改配置,或任何需要读者准确知道哪一行被改动的场景。

## 用 tabs 展示多种实现

当同一个思路存在多种等价的实现方式时,把它们放进 tabs 中,避免页面变得过长。读者可以在保持相同上下文的前提下,选择自己正在使用的语言或框架。

````mdx title="docs/src/content/docs/example.mdx" showLineNumbers
import { Tabs, TabItem } from '@astrojs/starlight/components';

<Tabs>
	<TabItem label="Java">

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("你好");
    }
}
```

	</TabItem>
	<TabItem label="Kotlin">

```kotlin
fun main() {
    println("你好")
}
```

	</TabItem>
</Tabs>
````

只有当各个版本确实可以互相替代时,才应该使用 tabs。如果每个代码块讲的是同一流程中的不同步骤,应把它们拆分为独立的小节。

## 推荐用法

一段好的代码块通常包含三层上下文:语言、文件和值得关注的部分。

````mdx
```ts title="src/main.ts" showLineNumbers {4}
import { createApp } from "./app";
import { paymentPlugin } from "./plugins/payment";

const app = createApp();
app.use(paymentPlugin);
app.start();
```
````

这比下面这种"裸"代码块要好:

````mdx showLineNumbers
```
const app = createApp();
app.start();
```
````

第二个代码块虽然也能正常显示,但缺少上下文:不知道语言、不知道文件、也不知道哪一行是重点。

## 快速检查清单

在完成一个文档页面之前,请根据以下问题检查其中的代码块:

* 代码块是否声明了正确的语言标识符?
* 如果代码属于某个具体文件,是否已添加 `title`?
* `showLineNumbers` 是否真的有助于让说明更容易理解?
* 是否需要高亮改动的行或重要的行?
* 如果存在多种实现,使用 tabs 是否能让页面更易读?
* 如果这段代码是修改指南,`diff` 是否比两个独立代码块更清晰?

## 小结

代码块应当帮助读者快速理解并正确复制代码。请先从语言标识符开始,在有具体文件时添加 `title`,合理使用 `showLineNumbers` 和有意义的高亮,再根据需要选择 `diff` 或 tabs,让示例更加清晰。
