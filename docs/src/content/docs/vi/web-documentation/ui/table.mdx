Table là một trong những thành phần quan trọng nhất khi viết technical documentation.

Thay vì mô tả nhiều thông tin có cùng cấu trúc bằng các đoạn văn dài, bạn có thể sử dụng table để đặt chúng cạnh nhau và giúp người đọc nhanh chóng so sánh.

Ví dụ, thay vì viết:

:::note
TypeScript được sử dụng cho frontend. Java được sử dụng cho Android. Swift được sử dụng cho iOS.
:::

có thể viết:

| Platform | Language   |
| -------- | ---------- |
| Web      | TypeScript |
| Android  | Kotlin     |
| iOS      | Swift      |

Cách này đặc biệt hữu ích khi tài liệu cần trình bày:

* So sánh nhiều lựa chọn.
* Danh sách thuộc tính.
* API parameters.
* Configuration options.
* Environment variables.
* HTTP status codes.
* Supported platforms.
* Feature comparison.
* Version compatibility.
* Database fields.
* CLI commands.
* Keyboard shortcuts.

## 1. Cú pháp Table cơ bản

Một Markdown Table tối thiểu gồm:

1. Header row.
2. Separator row.
3. Một hoặc nhiều data row.

**Mã nguồn**

```mdx showLineNumbers title="Table cơ bản"
| Name | Type | Description |
| --- | --- | --- |
| `id` | `string` | Unique identifier |
| `name` | `string` | User name |
| `email` | `string` | User email |
```

**Thử nghiệm**

| Name    | Type     | Description       |
| ------- | -------- | ----------------- |
| `id`    | `string` | Unique identifier |
| `name`  | `string` | User name         |
| `email` | `string` | User email        |

Dòng:

```md
| --- | --- | --- |
```

được sử dụng để phân tách header và nội dung.

Số lượng dấu `---` không quan trọng miễn là phần phân cách hợp lệ.

Ví dụ:

```md
| Name | Type |
| - | - |
| id | string |
```

vẫn có thể được render thành table.

Tuy nhiên, nên sử dụng `---` để source code dễ đọc hơn.

## 2. Header của Table

Header là hàng đầu tiên của table và dùng để mô tả ý nghĩa của từng column.

Ví dụ:

**Mã nguồn**

```mdx showLineNumbers title="Table có Header"
| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | User identifier |
| `name` | `string` | Yes | User name |
| `avatar` | `string` | No | Avatar URL |
```

**Thử nghiệm**

| Property | Type     | Required | Description     |
| -------- | -------- | -------- | --------------- |
| `id`     | `string` | Yes      | User identifier |
| `name`   | `string` | Yes      | User name       |
| `avatar` | `string` | No       | Avatar URL      |

Header nên ngắn gọn và dễ hiểu.

Không nên:

| This is the property name of the object | This is the data type of the property | Is this property required? |
| --------------------------------------- | ------------------------------------- | -------------------------- |

Nên:

| Property | Type | Required |
| -------- | ---- | -------- |

Header càng ngắn thì table càng dễ scan.

## 3. Số lượng Column

Mỗi row nên có cùng số lượng column.

**Mã nguồn**

```mdx showLineNumbers title="Số lượng Column"
| Name | Type | Description |
| --- | --- | --- |
| `id` | `string` | Identifier |
| `name` | `string` | User name |
| `email` | `string` | Email |
```

**Thử nghiệm**

| Name    | Type     | Description |
| ------- | -------- | ----------- |
| `id`    | `string` | Identifier  |
| `name`  | `string` | User name   |
| `email` | `string` | Email       |

Không nên tạo table với số lượng column không nhất quán:

```md
| Name | Type | Description |
| --- | --- | --- |
| id | string |
| name | string | User name | Extra |
```

Một số Markdown renderer có thể cố gắng tự sửa cấu trúc này, nhưng kết quả giữa các parser có thể khác nhau.

Vì vậy, hãy đảm bảo mỗi row có đúng số column.

:::caution[Cảnh báo]
Row thiếu hoặc thừa column so với header là lỗi rất dễ mắc phải khi copy-paste hoặc chỉnh sửa table thủ công. Hãy kiểm tra lại số lượng dấu `|` trên mỗi row trước khi commit.
:::

## 6. Căn chỉnh Column

Markdown Table hỗ trợ căn trái, căn phải và căn giữa bằng dấu `:`.

### Căn trái

```md
| Name | Type |
| :--- | :--- |
| id | string |
```

### Căn giữa

```md
| Name | Type |
| :---: | :---: |
| id | string |
```

### Căn phải

```md
| Name | Type |
| ---: | ---: |
| Price | 100 |
```

Có thể kết hợp cả ba.

**Mã nguồn**

```mdx showLineNumbers title="Column Alignment"
| Property | Type | Required | Default |
| :--- | :---: | :---: | ---: |
| `id` | `string` | Yes | - |
| `limit` | `number` | No | 20 |
| `enabled` | `boolean` | No | true |
```

**Thử nghiệm**

| Property  |    Type   | Required | Default |
| :-------- | :-------: | :------: | ------: |
| `id`      |  `string` |    Yes   |       - |
| `limit`   |  `number` |    No    |      20 |
| `enabled` | `boolean` |    No    |    true |

### Độ rộng Column

Markdown Table chuẩn **không có cú pháp để khai báo độ rộng cố định** cho một column, kể cả `:---` hay `---:` cũng chỉ điều khiển alignment, không điều khiển width.

```md
| Name | Description |
| --- | --- |
| id | Unique identifier |
```

Độ rộng thực tế mà trình duyệt hiển thị được tính tự động dựa trên nội dung dài nhất trong column đó, không phụ thuộc vào số dấu `-` bạn viết trong hàng phân cách.

:::caution[Cảnh báo]
Viết nhiều dấu `-` hơn (ví dụ `----------`) cho một column với hy vọng nó sẽ rộng hơn khi render là hiểu lầm phổ biến. Điều đó chỉ giúp source code dễ đọc hơn, không ảnh hưởng đến kết quả hiển thị.
:::

Trong docs này, nếu thực sự cần kiểm soát width (ví dụ tránh một column quá hẹp hoặc quá rộng), thêm `[width=...]` hoặc `[w=...]` vào header của column đó.

:::danger[Lỗi thường gặp]
Chỉ dùng cú pháp dấu vuông `[width=...]` hoặc `[w=...]`. Không dùng `{width=...}`, `<width=...>` hay biến thể khác, vì MDX có thể hiểu `{...}` là JSX expression và làm trang build lỗi.
:::

Ví dụ ép column đầu rộng cố định `200px`, các column còn lại để trình duyệt tự tính:

```mdx showLineNumbers title="Ép width bằng Markdown Table"
| Name [width=200px] | Description |
| --- | --- |
| `id` | Unique identifier |
```

**Thử nghiệm**

| Name [width=200px] | Description |
| --- | --- |
| `id` | Unique identifier |

Phần `[width=...]` chỉ dùng để render layout, không hiển thị trong header. Cách này vẫn nên dùng có chừng mực, vì width cố định quá nhiều có thể làm table khó đọc trên mobile.

## 7. Khi nào nên căn trái, giữa và phải?

Không nên căn chỉnh ngẫu nhiên.

Một quy tắc đơn giản:

| Nội dung    | Alignment |
| ----------- | --------- |
| Text        | Left      |
| Description | Left      |
| Mã nguồn        | Left      |
| Status      | Center    |
| Boolean     | Center    |
| Number      | Right     |
| Price       | Right     |
| Percentage  | Right     |

Ví dụ:

**Mã nguồn**

```mdx showLineNumbers title="Alignment thực tế"
| Property | Type | Required | Default |
| :--- | :--- | :---: | ---: |
| `name` | `string` | Yes | - |
| `enabled` | `boolean` | No | `true` |
| `limit` | `number` | No | `20` |
| `timeout` | `number` | No | `5000` |
```

**Thử nghiệm**

| Property  | Type      | Required | Default |
| :-------- | :-------- | :------: | ------: |
| `name`    | `string`  |    Yes   |       - |
| `enabled` | `boolean` |    No    |  `true` |
| `limit`   | `number`  |    No    |    `20` |
| `timeout` | `number`  |    No    |  `5000` |

## 8. Inline Mã nguồn trong Table

Một trong những cách sử dụng table phổ biến nhất trong technical documentation là đặt Mã nguồn inline vào trong cell.

**Mã nguồn**

```mdx showLineNumbers title="Inline Mã nguồn"
| Property | Type | Description |
| --- | --- | --- |
| `id` | `string` | Unique identifier |
| `createdAt` | `Date` | Creation timestamp |
| `isActive` | `boolean` | Whether the user is active |
```

**Thử nghiệm**

| Property    | Type      | Description                |
| ----------- | --------- | -------------------------- |
| `id`        | `string`  | Unique identifier          |
| `createdAt` | `Date`    | Creation timestamp         |
| `isActive`  | `boolean` | Whether the user is active |

Đối với technical documentation, nên sử dụng inline Mã nguồn cho:

* Variable name.
* Function name.
* Class name.
* File name.
* Command.
* API parameter.
* Environment variable.
* Type.
* HTTP method.
* URL path.

Ví dụ:

```md
`DATABASE_URL`
`npm run dev`
`UserRepository`
`POST`
`/api/users`
```

## 20. Table có dấu `|` bên trong nội dung

Một vấn đề thường gặp là nội dung cell có ký tự `|`.

Ví dụ TypeScript union type:

```ts
"asc" | "desc"
```

Nếu viết trực tiếp:

```md
| Type |
| --- |
| `"asc" | "desc"` |
```

ký tự `|` có thể bị Markdown parser hiểu là separator của table.

:::danger
Quên escape `|` sẽ làm table bị parse sai cấu trúc — thường là dịch lệch column hoặc phá vỡ toàn bộ table bên dưới. Đây là lỗi khó phát hiện vì source trông vẫn hợp lệ, chỉ khi render mới lộ ra.
:::

Cách an toàn là escape:

**Mã nguồn**

```mdx showLineNumbers title="Escape Pipe Character"
| Parameter | Type |
| --- | --- |
| `order` | `"asc" \| "desc"` |
```

**Thử nghiệm**

| Parameter | Type              |
| --------- | ----------------- |
| `order`   | `"asc" \| "desc"` |

Ký tự `|` được viết thành:

```md
\|
```

khi cần xuất hiện như nội dung của cell.

## 22. Table responsive trên Mobile

Đây là vấn đề rất quan trọng đối với documentation website.

Một table có nhiều column:

| Property  | Type      | Required | Default | Description     | Example |
| --------- | --------- | -------- | ------- | --------------- | ------- |
| `timeout` | `number`  | No       | `5000`  | Request timeout | `3000`  |
| `retry`   | `boolean` | No       | `false` | Retry request   | `true`  |

có thể vượt quá chiều rộng màn hình mobile.

Không nên cố ép tất cả column co lại đến mức text trở nên khó đọc.

Một cách phổ biến là cho table scroll ngang.

Ví dụ CSS:

```css
table {
    width: 100%;
}

.table-wrapper {
    overflow-x: auto;
}
```

Nếu hệ thống documentation của bạn đã có CSS xử lý responsive table, không cần thêm wrapper thủ công cho từng table.

:::caution[Cảnh báo]
Table nhiều column rất dễ bị tràn hoặc vỡ layout trên mobile nếu không kiểm tra thực tế. Đừng chỉ xem trên desktop rồi giả định nó cũng ổn ở màn hình nhỏ.
:::

Điều quan trọng là kiểm tra table ở:

* Desktop.
* Tablet.
* Mobile.
* Dark mode.
* Zoom trình duyệt lớn.


## 25. Table không nên dùng để tạo Layout

Markdown Table không phải layout system.

Không nên làm:

```md
| Left Content | Right Content |
| --- | --- |
| Text... | Text... |
```

chỉ để tạo hai cột layout cho trang.

Nếu cần layout:

* Use CSS.
* Use component.
* Use grid/flex.
* Use MDX component.

Table nên đại diện cho **tabular data**.

:::caution[Cảnh báo]
Dùng table để dàn layout là một anti-pattern phổ biến khi porting nội dung từ nơi khác (Word, Notion, Confluence). Hãy chuyển những table kiểu này sang component hoặc CSS layout thay vì giữ nguyên.
:::

## 32. Gộp Row (Rowspan) bằng dấu `^^`

Markdown Table chuẩn **không hỗ trợ rowspan** — không có cú pháp gốc nào để một cell chiếm nhiều hàng.

Trong docs này, khi một cell ở đầu dòng chỉ chứa đúng hai ký tự `^^`, nó sẽ được hiểu là "gộp với cell phía trên, cùng column" thay vì để trống.

:::danger[Lỗi thường gặp]
Chỉ dùng đúng hai ký tự `^^` cho cell muốn gộp lên trên. Không thêm khoảng trắng hay ký tự khác trong cùng cell (ví dụ `^^ `, `^^abc`), vì khi đó cell sẽ được hiểu là text bình thường thay vì marker gộp row.
:::

**Mã nguồn**

```mdx showLineNumbers title="Rowspan với ^^"
| Tính năng | Tính năng nhỏ | Trạng thái |
| --- | --- | --- |
| Đăng nhập | Tài khoản Vlive | Đã làm |
| ^^ | Google | Đã làm |
| ^^ | Facebook | Đã làm |
```

**Thử nghiệm**

| Tính năng | Tính năng nhỏ | Trạng thái |
| --- | --- | --- |
| Đăng nhập | Tài khoản Vlive | Đã làm |
| ^^ | Google | Đã làm |
| ^^ | Facebook | Đã làm |

Kết quả render ra HTML là một cell duy nhất `Đăng nhập` với `rowspan` bằng số dòng liên tiếp bên dưới có `^^` ở cùng column, các cell `^^` đó không còn tồn tại trong hàng của chúng.

Một vài lưu ý khi dùng:

* `^^` chỉ gộp với cell **ngay phía trên**, không gộp xuyên qua các dòng khác đã bị ngắt bởi một giá trị khác.
* `^^` có thể dùng cho bất kỳ column nào, không chỉ column đầu tiên.
* Không dùng `^^` ở hàng đầu tiên của phần dữ liệu (ngay sau header) vì không có cell nào phía trên để gộp.
* Chỉ nên dùng khi các row thực sự cùng thuộc một nhóm logic (ví dụ nhiều tính năng con của cùng một tính năng cha), không dùng để "sửa lỗi hiển thị" cho table không liên quan.

## Tóm tắt

Table trong MDX thực chất sử dụng cú pháp Markdown Table và không cần component riêng cho những trường hợp thông thường.

Cấu trúc cơ bản:

```mdx showLineNumbers title="Basic Table"
| Column 1 | Column 2 | Column 3 |
| --- | --- | --- |
| Value | Value | Value |
| Value | Value | Value |
```

Nguyên tắc quan trọng nhất:

1. **Header phải rõ ràng.**
2. **Mỗi row nên có cùng số column.**
3. **Text thường căn trái.**
4. **Status/boolean thường căn giữa.**
5. **Number thường căn phải.**
6. **Tên property, type, command và API parameter nên dùng inline Mã nguồn.**
7. **Table quá rộng nên được tách nhỏ hoặc hỗ trợ horizontal scrolling.**
8. **Không sử dụng table để làm layout.**
9. **Không dùng Markdown Table cho dữ liệu cần interaction phức tạp.**
10. **Với technical documentation, hãy ưu tiên table ngắn, có cấu trúc và dễ scan.**

Một table tốt không phải là table chứa được nhiều thông tin nhất, mà là table giúp người đọc **tìm đúng thông tin cần thiết nhanh nhất**.
